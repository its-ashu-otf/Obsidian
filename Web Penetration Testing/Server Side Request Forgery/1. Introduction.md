## What is SSRF?

SSRF stands for **Server-Side Request Forgery**. It’s a security vulnerability that allows an attacker to trick a server into making unintended requests to other resources, either within the same system (internal network) or to external systems. This happens because the server trusts input from the user without properly validating or restricting it.

### Simple Explanation
Imagine a server is like a librarian who fetches books for you. You tell the librarian, "Get me this book," and they trust you completely. Now, if you say, "Get me the secret staff records from the back office," and the librarian does it without checking, that’s a problem! SSRF is similar—the attacker sends a request through the server, and the server blindly follows it, potentially exposing sensitive data or systems.

### How It Works
- The attacker sends a crafted input (like a URL) to an application.
- The server processes this input and makes a request to that URL.
- If the URL points to something sensitive (e.g., an internal database or another website), the server might fetch and expose it to the attacker.

### Example
Let’s say there’s a web app that lets you check the weather by entering a city name. The app sends a request to a weather API like this:
```css
http://weather-api.com?city=London
```
The server takes your input ("London") and builds the request. Now, an attacker changes the input to trick the server into requesting something else, like:
```css
http://localhost:8080/admin
```
If the server isn’t protected, it might fetch the internal admin page (meant only for staff) and send it back to the attacker.
