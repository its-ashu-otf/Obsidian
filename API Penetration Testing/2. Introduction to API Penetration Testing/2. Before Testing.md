# Checklist before start testing


### **1. Questions to Ask the Client:**

![[Pasted image 20250429171029.png]]
- **API Architecture:** What type is the API? (SOAP, REST, GraphQL, RPC, Webhooks, etc.)
- **Testing Type:** Whitebox, blackbox, or greybox testing?
- **Environment:** Will testing occur in production, pre-production, or quality environment?
- **Authentication:** What authentication methods are used? (Basic Auth, OAuth 2.0, none)
- **User Roles:** What user roles exist (low privilege, regular user, admin)?
- **Documentation:** Is there documentation available? (Open API Specification, reference docs, etc.)
  - **Purpose:** Helps in saving time, and for testing vulnerabilities like "Improper Inventory Management" (OWASP API Security Top 10, 2023).

---

### **2. Tasks to Perform During API Pen Testing:**
- **Use the API as Designed:** Familiarize with workflows, methods, and endpoints.
- **Write Use Cases:** (Optional) Create a checklist for penetration testing.
- **Create an API Testing Methodology:** Use existing frameworks like OWASP API Security Top 10 or ASVS, or create a custom methodology.

---

### **3. Tools for API Penetration Testing:**
- **Documentation Tools:** Use tools like Cherry Tree (avoid cloud apps like Notion).
- **Penetration Testing Tools:**
  - **Burp Suite** – Widely used for manual and automated API security testing.
  - **Postman** – Helps with testing API endpoints.
  - **APIsec University Scan** – Automated tool to streamline testing and vulnerability identification.

---

### **4. Using APIsec Scan (for Automation):**
- **Import the API:**
  - Options include Open API Specification, Postman, AWS, etc.
  - Upload API specification (e.g., JSON file) and onboard the instance (e.g., crapi.apisec.ai).
  
- **Scan the API:**
  - Choose between unauthenticated or authenticated scans (configure credentials for authenticated scans).
  - Review results in **Threat Detection** and **Vulnerabilities** tabs.
  
- **Vulnerability Details:**
  - View vulnerabilities by category, test type, attack vector, severity, and CVSS score.
  - **Remediations:** Provides remediation details per category for fixing vulnerabilities quickly.

---

### **5. API Discovery Methods:**
- **Manual API Discovery:**
  - Ideal for a detailed understanding of complex systems.
  - Time-consuming and error-prone.
  - Tools used: Wireshark (for network traffic analysis), source code/bytecode review, and documentation.
  
- **Automated API Discovery:**
  - Fast and scalable, but may miss certain nuances.
  - Tools used: OWASP ZAP, Amass, KiteRunner, WFuzz, Burp Suite, Postman.
  
- **Best Practice:** Combine both **manual** and **automated** discovery to ensure accuracy and completeness.

---

### **6. Report and Remediation:**
- **Penetration Testing Report:**
  - Includes vulnerabilities with CVSS score, severity, and age.
  - Detailed categorization of vulnerabilities (authentication, response headers, info leaks, etc.).
  
- **Remediation:** 
  - Crucial for security and IT teams to fix vulnerabilities efficiently.
  - Provides actionable recommendations per category (authentication, injection, etc.).

---

### **7. Final Thoughts:**
- Use **APIsec Scan** to automate scanning and streamline API penetration testing.
- **Manual discovery** is ideal for complex systems, but it’s best combined with **automated tools** for scalability.
- Prioritize **remediation** steps to help clients fix vulnerabilities quickly and securely.
