### 🧠 **What is Pass-the-Hash (PtH)?**

**Pass-the-Hash** is a post-exploitation technique that allows an attacker to authenticate to a remote system or service **without knowing the plaintext password**, by using the **NTLM (or sometimes LM) hash** of the password instead.

- Instead of cracking the hash, the attacker **uses the hash directly** in place of a password.
    
- This works because in many NTLM-based authentication scenarios (especially with SMB and RPC), the actual password is not required—only the hash is.

### 🧰 **Tools Commonly Used for PtH**

1. **Metasploit PsExec module**
    
    - `exploit/windows/smb/psexec` or `psexec_psh`
        
    - Takes username and NTLM hash to spawn a session on the target.
        
2. **CrackMapExec**
    
    - One-liner example:
        
        ```bash
        crackmapexec smb 192.168.1.10 -u Administrator -H <NTLM_HASH>
        ```
        
3. **Impacket's `psexec.py`, `wmiexec.py`, or `smbexec.py`**
    
    - Supports `-hashes` argument:
        
        ```bash
        psexec.py -hashes <LM>:<NTLM> DOMAIN/Administrator@192.168.1.10
        ```
        
4. **Mimikatz**
    
    - Used to extract hashes from memory (`sekurlsa::logonpasswords`) or perform **"overpass-the-hash"** attacks.
        

---

### ⚙️ **How PtH Works (Simplified Flow)**

1. **Obtain NTLM Hashes**  
    Via:
    
    - Dumping from memory using Mimikatz
        
    - Extracting from the SAM file
        
    - Sniffing NTLM authentication over the network
        
2. **Use the Hash to Authenticate**  
    The hash is presented as-is in the NTLM authentication process without needing the password.
    
3. **Establish Access**  
    Tools use the hash to spawn shells, execute commands, or pivot.
    

---

### 🛡️ **Why it Works**

- Windows authentication protocols like **NTLM** do not require the actual password, just a response that can be derived from the hash.
    
- Poor **segmentation**, **admin reuse**, and **lack of SMB signing** make lateral movement easy once one hash is obtained.
    

---

### 🔐 **Defenses Against PtH**

1. **Use Kerberos where possible** (not NTLM)
    
2. **Enable Windows Credential Guard** (isolates credentials)
    
3. **Apply LSA Protection**
    
4. **Implement SMB signing**
    
5. **Avoid local admin reuse** across machines
    
6. **Use strong monitoring and logging** (detect abnormal SMB/RPC auths)
    

---

### ✅ TL;DR (Quick Summary)

- **Pass-the-Hash** lets you authenticate with a hash instead of cracking it.
    
- Often used in **lateral movement** post-exploitation.
    
- Supported by tools like **Metasploit**, **CrackMapExec**, **Impacket**, and **Mimikatz**.
    
- Works because **NTLM accepts a hash as proof of identity**.
    
- Defend by **segmentation**, **hardening**, and **NTLM deprecation**.
