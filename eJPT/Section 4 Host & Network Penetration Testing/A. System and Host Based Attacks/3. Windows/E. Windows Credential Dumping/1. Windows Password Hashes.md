# Windows Password Hashes
### 1. **Password Storage – The SAM Database**

- Windows operating systems store **hashed user account passwords** locally in the **SAM (Security Accounts Manager)** database.
    
- The SAM file is located at:
    
    ```powershell
    C:\Windows\System32\config\SAM
    ```
    
- This file is **locked by the OS when in use**, so direct access requires special conditions, such as booting into another OS or using tools that bypass the file lock (e.g., Mimikatz, pwdump, or accessing the Volume Shadow Copy).
    

---

### 2. **Hashing Basics**

- **Hashing** is the process of converting data (like a plaintext password) into a fixed-size string of characters using a **one-way cryptographic function**.
    
- Common characteristics of hashing:
    
    - Deterministic (same input → same output)
        
    - Irreversible (not meant to be "decrypted")
        
    - Sensitive to change (even a 1-bit difference → different hash)
        
- The output is called a **hash** or **hash value**.
    

> 📌 As a pentester, understand that **hashes can be cracked offline** using brute-force or dictionary attacks if you obtain them, even though hashing is meant to be one-way.

---

### 3. **LSA (Local Security Authority)**

- **LSA (Local Security Authority)** is a Windows subsystem responsible for:
    
    - **Authenticating users** locally and over the network
        
    - Enforcing local security policies
        
    - Storing sensitive data in memory, such as **password hashes** and **Kerberos tickets**
        
- **LSASS.exe** is the process name that represents LSA.
    
    - Tools like **Mimikatz** target LSASS memory to extract credentials.
        

> 🎯 **Privilege escalation** to SYSTEM-level is often needed to dump hashes from LSASS memory. This is a key post-exploitation technique.

---

### 4. **Hash Types in Windows**

#### 🟠 LM Hash (LAN Manager Hash)

- Used in older Windows systems (pre-Vista and pre-2003).
    
- Major flaws:
    
    - Passwords are converted to **uppercase**.
        
    - Only the **first 14 characters** are used.
        
    - Password is split into two 7-character chunks → each chunk hashed separately → susceptible to brute-force.
        

#### 🟢 NTLM Hash (NT LAN Manager)

- Stronger than LM, used by default in:
    
    - **Windows NT and onwards**
        
    - **NTLMv1/NTLMv2** are authentication protocols using this hashing scheme.
        
- Stored in SAM database and Active Directory.
    

#### 🔒 Modern Windows (Vista and above):

- **LM hashing is disabled by default** for security reasons.
    
- NTLM is still supported for backward compatibility, but **Kerberos** is the preferred protocol for domain authentication.
    

> ⚠️ **As a pentester**, NTLM hashes can be reused in **pass-the-hash (PtH)** attacks without cracking them, especially in lateral movement scenarios.

---

## 🔍 Additional Pentester Insights

### 🧠 Where & How Hashes Can Be Extracted

- **Locally** (from SAM, LSASS memory, Volume Shadow Copies)
    
- **Remotely** (using tools like secretsdump.py from Impacket)
    
- **Post-exploitation**: Once SYSTEM access is achieved on a host
    

### 🧰 Tools Commonly Used:

- `Mimikatz`
    
- `secretsdump.py` (Impacket)
    
- `hashdump` in Meterpreter
    
- `crackmapexec` for lateral movement and hash passing
    
- `John the Ripper` / `Hashcat` for cracking hashes offline
    

---

## ✅ Defensive Measures (So You Know What to Look For):

- Disable LM hashes (`NoLMHash` registry key)
    
- Enforce strong password policies and lockout thresholds
    
- Restrict access to LSASS memory (Credential Guard / RunAsPPL)
    
- Limit lateral movement with segmentation and tiered accounts

# SAM Database
### ● **SAM (Security Account Manager)**

- The SAM database manages **local user accounts** and **hashed passwords** on Windows.
    
- These password hashes are not in plaintext; they’re cryptographically hashed and stored in:
    
    ```
    C:\Windows\System32\config\SAM
    ```
    

### ➕ **Additional Pentester Knowledge:**

- Only **local accounts** are stored here; domain accounts reside in the **NTDS.dit** database on Domain Controllers.
    
- Hashes in SAM can be dumped offline using tools like `samdump2`, `chntpw`, or `secretsdump.py` when paired with the SYSTEM hive.
    

---

### ● **SAM cannot be copied while the OS is running**

- The Windows NT kernel **locks** the SAM file during runtime to prevent direct access or copying.
    

### ➕ **Additional Pentester Knowledge:**

- This restriction can be **bypassed** by abusing the **Volume Shadow Copy Service (VSS)**:
    
    ```powershell
    vssadmin create shadow /for=C:
    copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopyX\Windows\System32\config\SAM .
    ```
    
- Tools like `secretsdump.py` and `Invoke-VssDump` automate this method.
    

---

### ● **Attackers use in-memory techniques to dump SAM hashes from LSASS**

- Since the SAM file is locked, attackers target the **LSASS process**, where credentials are stored in memory during authentication.
    

### ➕ **Additional Pentester Knowledge:**

- LSASS contains:
    
    - NTLM hashes
        
    - Kerberos tickets (TGTs, useful for Golden Ticket/Pass-the-Ticket)
        
    - Sometimes plaintext passwords (e.g., when WDigest is enabled)
        
- Common tools for dumping from LSASS:
    
    - `Mimikatz`
        
    - `ProcDump` + `Mimikatz` (for offline analysis)
        
    - `Nanodump` (OPSEC-safe alternative to Mimikatz)
        
    - `Pypykatz` (Python-based parsing of LSASS dumps)
        

---

### ● **SAM is encrypted with a syskey in modern Windows**

- Modern Windows systems encrypt the SAM file using a **boot key (syskey)** stored in the **SYSTEM registry hive**.
    

### ➕ **Additional Pentester Knowledge:**

- To decrypt SAM hashes offline, you need both:
    
    - `SAM` hive
        
    - `SYSTEM` hive (for extracting the boot key)
        
- Tools like `samdump2` or `secretsdump.py` can handle this automatically.
    

---

### ● **Admin privileges are required to access LSASS**

- Interacting with LSASS or dumping its memory requires **elevated (Administrator or SYSTEM)** permissions.
    

### ➕ **Additional Pentester Knowledge:**

- **Privilege escalation** is usually a prerequisite before dumping hashes from LSASS.
    
- **Defenses** to be aware of:
    
    - Credential Guard (prevents direct LSASS access)
        
    - RunAsPPL (requires LSASS to run as a protected process)
        
    - EDR tools monitoring LSASS memory access

# LM (LanMan)


## 🔓 LM Hashing – Legacy Protocol Breakdown

### ● **LM (LAN Manager) Hashing Overview**

- **LM** was the **default password hashing algorithm** used in Windows operating systems **before NT 4.0**.
    
- It is now obsolete and **disabled by default** in modern Windows versions (Vista and later), but it may still exist in **legacy systems** or **mixed-domain environments**.
    

---

### ● **LM Hashing Process (Step-by-Step)**

![[Pasted image 20250610213435.png]]

1. The plaintext password is padded or truncated to **14 characters max**.
    
2. It is split into **two 7-character chunks**.
    
3. All characters are **converted to uppercase** (case is destroyed).
    
4. Each 7-character chunk is:
    
    - Converted into a 56-bit DES key.
        
    - Used to **DES-encrypt a constant value** (usually `"KGS!@#$%"`).
        
    - The result of each DES encryption becomes half the final hash.
        
5. The final LM hash is the **concatenation of both DES outputs**, totaling **16 bytes (128 bits)**.
    

---

### ● **Security Weaknesses of LM Hashing**

- **No salting**: Identical passwords always produce the same hash.
    
- **Password length cap**: Only the **first 14 characters** are considered.
    
- **Case-insensitive**: `"Password"` = `"PASSWORD"` = `"password"`.
    
- **Splitting makes it weak**: Each half of the hash can be cracked **independently** with rainbow tables or brute-force.
    
- **Extremely fast to crack**: Modern GPUs and rainbow tables can recover LM hashes in seconds to minutes.
    

---

### ➕ **Additional Pentester Knowledge**

- LM hashes are often included in the format:  
    `username:rid:LM_hash:NTLM_hash:::`
    
- Even if the **LM hash field is empty**, NTLM can still be cracked or passed.
    
- **Example LM hash of a blank password:**
    
    ```
    aad3b435b51404eeaad3b435b51404ee
    ```
    
    This tells you the system **stored an empty LM hash** — a common case in modern OS where LM is disabled.
    
- Tools like `Ophcrack`, `John the Ripper`, and `Hashcat` can crack LM hashes extremely fast using precomputed rainbow tables.

# NTLM (NTHash)

### ● **What is NTLM?**

- **NTLM (NT LAN Manager)** is a **suite of authentication protocols** used by Windows systems to authenticate users **locally** or in **domain environments without Kerberos**.
    
- Authentication relies on providing a **valid username and password** that are hashed and compared during the login process.
    

---

### ● **NTLM vs LM**

- From **Windows Vista onward**, **LM hashing is disabled** by default.
    
- **NTLM replaces LM** as the default local authentication mechanism.
    
- NTLM offers significantly **stronger security** over LM but still has known weaknesses.
    

---

### ● **NTLM Hashing Process (Key Detail)**

![[Pasted image 20250610213935.png]]

- When a user account is created or a password is changed, the password is:
    
    - **Hashed using MD4**, a fast but now cryptographically weak algorithm.
        
    - The original plaintext password is **discarded** after hashing.
        
    - No salt is used → identical passwords = identical hashes across machines.
        

> 🔎 NTLM hash = `MD4(UTF-16-LE(password))`

---

### ● **NTLM Improvements Over LM**

- ✅ **No chunk splitting**: The password is hashed as a whole — not split into 7-character segments like LM.
    
- ✅ **Case-sensitive**: Preserves uppercase and lowercase distinctions.
    
- ✅ **Supports complex passwords**: Includes **symbols, numbers, and Unicode characters**, improving entropy.
    

---

### ➕ **Additional Pentester Knowledge**

- NTLM hashes can be **passed** in network authentication without needing the plaintext password – known as **Pass-the-Hash (PtH)**.
    
- **Still crackable offline** if captured from SAM, LSASS, or intercepted via network protocols like SMB or NTLM challenge-response.
    
- Common attack vectors:
    
    - `secretsdump.py` (remote hash dump via SMB/RPC)
        
    - `Mimikatz` (LSASS memory dump)
        
    - `Responder` or `Inveigh` (NTLM relay attacks via LLMNR/NBNS spoofing)
        
- NTLMv1 is weaker and still seen in legacy systems. **NTLMv2** is stronger but **still vulnerable to relay attacks** if SMB signing isn't enforced.
