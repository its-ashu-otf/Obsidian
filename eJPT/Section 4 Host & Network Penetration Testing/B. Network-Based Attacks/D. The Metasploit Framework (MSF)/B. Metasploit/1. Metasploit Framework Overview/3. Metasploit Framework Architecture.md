# MSF Architecture

![[Pasted image 20250615222317.png]]

- A module in the context of MSF, is a piece of code that can be utilized by the MSF.
- The MSF libraries facilitate the execution of modules without having to write the code necessary in order to execute them.

## 🔧 **MSF Modules Overview**

### 1. **Exploit**

- **Purpose**: Takes advantage of a vulnerability in a target system.
    
- **Usage**: Paired with a payload to execute code on the target.
    

### 2. **Payload**

- **Purpose**: The actual code executed on the target after successful exploitation.
    
- **Example**: `windows/meterpreter/reverse_tcp` – opens a reverse shell from victim to attacker.
    

### 3. **Encoder**

- **Purpose**: Obfuscates payloads to avoid antivirus/endpoint detection.
    
- **Example**: `shikata_ga_nai` – polymorphic XOR additive feedback encoder (Windows payloads).
    

### 4. **NOPS (No Operation Instructions)**

- **Purpose**:
    
    - Acts as filler to maintain payload size.
        
    - Ensures stability during execution.
        
- **Example**: NOP sled (`\x90` in x86) helps slide into shellcode.
    

### 5. **Auxiliary**

- **Purpose**: Provides functions beyond exploitation.
    
- **Use Cases**:
    
    - Scanning (`scanner/portscan/tcp`)
        
    - Enumeration
        
    - DoS attacks
        
    - Services interaction (e.g., SMTP, FTP, SNMP)
        

---

## 🧬 **MSF Payload Types**

### 1. **Non-Staged Payloads**

- **Definition**: Entire payload is sent in one go with the exploit.
    
- **Example**: `windows/shell_reverse_tcp`
    
- **Pros**: Simpler; no staging needed.
    
- **Cons**: Larger size; easier to detect.
    

### 2. **Staged Payloads**

- **Definition**: Payload is split into:
    
    - **Stager**: Connects back to attacker.
        
    - **Stage**: Downloads and executes final payload (like Meterpreter).
        
- **Example**: `windows/meterpreter/reverse_tcp`
    
- **Pros**: Smaller initial payload; stealthier.
    
- **Cons**: More complex; can fail if connection breaks.
    

---

## 🧱 **Stagers vs. Stages**

### 🔹 **Stager**

- **Purpose**: Creates a communication channel.
    
- **Function**: Used to deliver the "stage" (main payload).
    
- **Example**: Reverse TCP stager.
    

### 🔹 **Stage**

- **Purpose**: The main payload functionality.
    
- **Function**: Offers advanced post-exploitation capabilities.
    
- **Example**: Meterpreter shell, VNC inject, etc.
    

---

## 🧠 **Meterpreter Payload**

- **Type**: Advanced stage payload.
    
- **Executed**: In-memory (avoids writing to disk = stealthier).
    
- **Features**:
    
    - File system navigation
        
    - Command execution
        
    - Screenshot capture
        
    - Keylogging
        
    - Pivoting and tunneling
        
    - Process migration
        
- **Communication**: Over the stager’s channel (e.g., TCP, HTTPS).

# MSF File System Structure

The MSF file system is organized in a simple and easy to understand format and is organized into various directories.

![[Pasted image 20250615222836.png]]

## MSF Module Locations 
- MSF stores modules under the following directory on Linux systems: 
		`/usr/share/metasploit-framework/modules` 
- User specified modules are stored under the following directory on Linux systems: 
		`~/.ms4/modules`
