
## 🧠 Network Protocols

- **Definition**: A **network protocol** is a set of standardized rules that define how data is formatted, transmitted, and received across networks.
    
- **Purpose**: They enable interoperability between systems with different hardware/software architectures—ensuring structured communication.
    
- **Examples**:
    
    - **TCP/IP** – Core suite of protocols enabling the internet (IP addressing, reliable delivery via TCP).
        
    - **HTTP/HTTPS** – Used for web communication.
        
    - **FTP/SFTP** – Used for file transfer.
        
    - **DNS** – Resolves domain names to IP addresses.
        
    - **ICMP** – Used for diagnostic messages (e.g., ping).
        
    - **DHCP** – Automatically assigns IP addresses.
        
- **Types of Protocols** (based on OSI layers):
    
    - **Application Layer**: HTTP, DNS, SMTP
        
    - **Transport Layer**: TCP, UDP
        
    - **Network Layer**: IP, ICMP
        
    - **Data Link Layer**: ARP, Ethernet

## 📦 Packets

- **Definition**: A **packet** is a formatted unit of data carried by a packet-switched network.
    
- **Purpose**: It encapsulates the data being transferred, along with metadata like sender/receiver IPs, port numbers, sequence numbers, etc.
    
- **Composition**: Typically contains:
    
    - **Header**: Contains control information (protocols, IP addresses, ports)
        
    - **Payload**: The actual data (e.g., part of an email or web page)
        
    - **Trailer** (sometimes): Used for error-checking (like CRC in Ethernet)
        
- **Transmission**:
    
    - Packets travel through physical media (e.g., Ethernet cables, Wi-Fi) as **electric signals** or **radio waves**.
        
    - Routers and switches interpret and forward these packets using the **destination IP address and MAC address**.

## 🔁 Key Concepts to Understand

|Concept|Description|
|---|---|
|**Protocol Stack**|Layered structure (e.g., OSI or TCP/IP model) allowing modular communication.|
|**Encapsulation**|Wrapping data with protocol-specific headers/trailers at each layer.|
|**Fragmentation**|Large packets broken down to fit MTU (Maximum Transmission Unit).|
|**Packet Switching**|Method where data is split into packets that are routed independently.|

## 📚 **The OSI Model – Explained**

### 🔍 What is It?

- The **OSI (Open Systems Interconnection)** model is a **conceptual framework** developed by the **ISO** to **standardize** how data is transmitted over a network.
    
- It **abstracts complex networking processes** into **7 distinct layers**, each with a **specific role**, helping vendors and engineers **design interoperable systems** and troubleshoot efficiently.
    

---

## 🧱 **The 7 OSI Layers (Top → Bottom)**

|#|Layer|Function|Real-World Examples|
|---|---|---|---|
|7|**Application**|Interface for end-user services and applications|HTTP, FTP, DNS, SSH, Telnet|
|6|**Presentation**|Translates data formats, handles encryption & compression|SSL/TLS, Base64, JPEG, MP3|
|5|**Session**|Manages sessions, authentication, and dialog control|NetBIOS, RPC, PPTP|
|4|**Transport**|Provides reliable/unreliable delivery, segmentation, and flow control|TCP, UDP, SCTP|
|3|**Network**|Handles routing, logical addressing (IP addresses)|IP, ICMP, IPSec, RIP, OSPF|
|2|**Data Link**|Responsible for MAC addressing, error detection, and framing|Ethernet, ARP, VLAN, Switches|
|1|**Physical**|Transmits raw bit stream over physical medium|Cables, NICs, Hubs, Fiber, Radio|

---

## 🔐 Practical Security Relevance (From a Pentester’s View)

- **Layer 7 (Application)** – Target of **most attacks**: XSS, SQLi, SSRF, RCE, etc.
    
- **Layer 4 (Transport)** – Port scanning, DoS/DDoS, TCP flag manipulation.
    
- **Layer 3 (Network)** – IP spoofing, routing attacks, ICMP-based enumeration.
    
- **Layer 2 (Data Link)** – ARP spoofing, MAC flooding, switch port abuse.
    
- **Layer 1 (Physical)** – Tap into network physically (air-gapped systems, sniffing via hardware tools).

## 🧠 Key Concepts & Tips

|Concept|Meaning|
|---|---|
|**Encapsulation**|Data is wrapped with headers/trailers at each layer (e.g., segment → packet → frame → bits)|
|**Decapsulation**|On the receiving end, headers are stripped as data moves up the stack|
|**PDU (Protocol Data Unit)**|Varies per layer: App = Data, Transport = Segment, Network = Packet, Data Link = Frame, Physical = Bits|
|**"All People Seem To Need Data Processing"**|Mnemonic (L7 → L1) to remember the layers|
|**OSI vs TCP/IP**|TCP/IP has 4 layers: Application, Transport, Internet, Link — it’s the **real-world implementation**|

## 🔧 Real-World Application

- **Wireshark Filters**: You’ll spot OSI-layer interactions (e.g., follow TCP streams, inspect TLS handshake at Layer 6, etc.)
    
- **Firewall Rules**: Often operate at **Layer 3 (IP)** and **Layer 4 (TCP/UDP)**
    
- **Proxy Servers**: Operate at **Layer 7**, can inspect HTTP/S content
    
- **Switches vs Routers**:
    
    - **Switches**: Layer 2 (MAC-based forwarding)
        
    - **Routers**: Layer 3 (IP-based forwarding)
