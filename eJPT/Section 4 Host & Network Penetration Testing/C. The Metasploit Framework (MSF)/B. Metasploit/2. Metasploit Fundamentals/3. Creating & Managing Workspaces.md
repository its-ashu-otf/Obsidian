### 🔍 **What is a Workspace in MSF?**

Think of a workspace like a **project folder**. It stores:

- Hosts you've scanned
    
- Services identified
    
- Exploits attempted
    
- Session data
    
- Loot collected


This way, you don’t mix up results between different targets/orgs.

---

### 🛠️ **Core Workspace Commands**

Here’s how to manage them in `msfconsole`:

#### 🔹 List All Workspaces

```bash
workspace
```

#### 🔹 Create a New Workspace

```bash
workspace -a <name>
```

Example:

```bash
workspace -a acme_corp
```

#### 🔹 Switch to a Workspace

```bash
workspace <name>
```

Example:

```bash
workspace acme_corp
```

#### 🔹 Delete a Workspace

```bash
workspace -d <name>
```

#### 🔹 Rename a Workspace _(Not supported directly)_

Metasploit doesn’t support renaming a workspace directly. You’ll have to:

- Export data
    
- Create a new workspace
    
- Import again (manual workaround)
    

---

### 🔁 **Using Workspaces Effectively**

- **One target/company = one workspace**
    
- Combine with `db_nmap` to populate hosts & services into the DB:
    
    ```bash
    db_nmap -sS -A 10.0.0.0/24
    ```
    
- Use `hosts`, `services`, `vulns`, `loot`, etc., to manage and query data inside that workspace.
    

---

### 🔍 Example Workflow

```bash
workspace -a corp_target
workspace corp_target
db_nmap -sV 192.168.1.0/24
hosts
services
```

---

### 🧠 Pro Tips

- Always **start by creating a workspace** before running any scans.
    
- Workspaces are stored in the Metasploit DB — so don’t nuke it unless you’ve backed up the data.
    
- Use with `notes`, `creds`, and `loot` for full engagement tracking.

### ✅ **Officially Supported Workspace Flags:**

You can verify these by typing `workspace -h` in `msfconsole`.

|Command|Function|
|---|---|
|`workspace`|List workspaces|
|`workspace -a`|Add new workspace|
|`workspace -d`|Delete workspace|
|`workspace -h`|Show help|

---

### 🛠️ **Workaround to "Rename" a Workspace**

If you **really** need to rename one, follow this workaround:

1. **Create a new workspace**:
    
    ```bash
    workspace -a new_name
    ```
    
2. **Switch to the old one and export its data** (optional if using db_nmap, notes, etc.)
    
3. **Manually recreate findings** in the new one.
    
4. **Delete the old workspace**:
    
    ```bash
    workspace -d old_name
    ```
    

---
