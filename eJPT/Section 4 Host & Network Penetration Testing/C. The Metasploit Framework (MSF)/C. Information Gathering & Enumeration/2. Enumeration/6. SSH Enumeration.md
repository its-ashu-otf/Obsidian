
### 🔍 SSH Enumeration

- **What is SSH?**
    
    - **SSH (Secure Shell)** is a protocol used for secure **remote administration** and **file transfers**.
        
    - Provides strong encryption and authentication mechanisms.
        
    - It's the secure replacement for older protocols like **Telnet** and **rlogin**.
        
- **Default Port**
    
    - Runs on **TCP port 22** by default.
        
    - Can be configured to run on **any TCP port**, especially in hardened systems—so full port scans are necessary.
        

---

### 🛠️ Enumeration Techniques

- **Service Detection**
    
    - Use `nmap` for version and script-based detection:
        
        ```bash
        nmap -sV -p 22 <target-ip>
        nmap -p 22 --script ssh2-enum-algos,ssh-hostkey,ssh-auth-methods <target-ip>
        ```
        
        - `ssh2-enum-algos`: Enumerates supported algorithms (useful for identifying weak configs).
            
        - `ssh-hostkey`: Extracts SSH host key fingerprints.
            
        - `ssh-auth-methods`: Lists allowed authentication methods (e.g., password, publickey).
            
- **Banner Grabbing**
    
    - Manually grab the banner using:
        
        ```bash
        nc <target-ip> 22
        ```
        
        or
        
        ```bash
        ssh -v <target-ip>
        ```
        
        - Look for version disclosures like `OpenSSH_7.2p2`, which can be checked for known vulnerabilities.
            
- **Brute-Force Attacks (Metasploit Example)**
    
    ```
    use auxiliary/scanner/ssh/ssh_login
    set RHOSTS <target-ip>
    set USER_FILE /usr/share/wordlists/usernames.txt
    set PASS_FILE /usr/share/wordlists/passwords.txt
    run
    ```
    
- **Hydra Example**
    
    ```bash
    hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://<target-ip>
    ```
    
- **Key-Based Access Checks**
    
    - If you obtain SSH private keys (from backups, leaks, or other compromised systems), try to authenticate using:
        
        ```bash
        ssh -i id_rsa user@target-ip
        ```

### ⚠️ Misconfigurations and Weaknesses to Exploit

- **Password Authentication Enabled**
    
    - Many systems still allow password-based logins, making brute-force feasible.
        
- **Old or Vulnerable OpenSSH Versions**
    
    - E.g., OpenSSH < 7.4 has known buffer overflow CVEs (CVE-2016-10009, etc.)
        
- **Weak or Default Credentials**
    
    - Often overlooked by admins (especially in dev or staging environments).
        
- **SSH Trust Relationships**
    
    - Once access is gained, inspect `~/.ssh/authorized_keys` and `known_hosts` for possible **pivot points**.
        
- **SSH Misconfigurations**
    
    - Public key auth misused.
        
    - Root login allowed via SSH (`PermitRootLogin yes` in `sshd_config`).
        

---

### 🧠 Post-Exploitation Tips

- **Enumerate User Access**
    
    - Check `~/.bash_history`, `~/.ssh/`, cron jobs, and sudo permissions.
        
- **Lateral Movement**
    
    - Use SSH keys or credentials to jump to other hosts (especially if `~/.ssh/id_rsa` is reused across systems).
        
- **Persistence**
    
    - Add your own key to `~/.ssh/authorized_keys`.
