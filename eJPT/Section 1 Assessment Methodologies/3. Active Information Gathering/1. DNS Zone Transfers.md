+ Domain Name System (DNS) is a protocol that is used to resolve domain names/hostnames to IP addresses.
+ During the early days of the internet, users would have to remember the IP addresses of the sites that they wanted to visit, DNS resolves this issue by mapping domain names (easier to recall) to their respective IP addresses.
+ A DNS server (nameserver) is like a telephone directory that contains domain names and their corresponding IP addresses.
+ A plethora of public DNS servers have been set up by companies like Cloudflare (1.1.1.1) and Google (8.8.8.8). These DNS servers contain the records of almost all domains on the internet.


## DNS Records
---

### ✅ **1. A Record (Address Record)**

- **What it does:** Maps a domain name to an **IPv4** address.
    
- **Example:**  
    `example.com → 93.184.216.34`
    

---

### ✅ **2. AAAA Record**

- **What it does:** Maps a domain name to an **IPv6** address.
    
- **Example:**  
    `example.com → 2606:2800:220:1:248:1893:25c8:1946`
    

---

### ✅ **3. NS Record (Name Server)**

- **What it does:** Points to the name servers for a domain (the servers responsible for answering DNS queries).
    
- **Example:**  
    `example.com → ns1.exampledns.com, ns2.exampledns.com`
    

---

### ✅ **4. MX Record (Mail Exchange)**

- **What it does:** Points email traffic to the domain's **mail server**.
    
- **Example:**  
    `example.com → mail.example.com (priority 10)`
    

---

### ✅ **5. CNAME Record (Canonical Name)**

- **What it does:** Maps a domain **alias** to another domain (like a nickname).
    
- **Example:**  
    `www.example.com → example.com`  
    (So if you go to `www.example.com`, it redirects to `example.com`.)
    

---

### ✅ **6. TXT Record**

- **What it does:** Stores **text** information, usually for verification or security (e.g., SPF, DKIM).
    
- **Example:**  
    `example.com → "v=spf1 include:_spf.google.com ~all"`  
    (Used to prevent email spoofing.)
    

---

### ✅ **7. HINFO Record (Host Information)**

- **What it does:** Gives info about the **host's hardware and OS**.
    
- **Example:**  
    `example.com → "CPU: Intel", "OS: Windows"`
    

---

### ✅ **8. SOA Record (Start of Authority)**

- **What it does:** Contains **important info about the domain**, like the admin email, serial number, and refresh time.
    
- **Example:**  
    `example.com → primary DNS: ns1.example.com, admin: hostmaster@example.com`
    

---

### ✅ **9. SRV Record (Service Record)**

- **What it does:** Specifies info about **services** available in the domain (e.g., SIP, XMPP).
    
- **Example:**  
    `_sip._tcp.example.com → sipserver.example.com:5060`
    

---

### ✅ **10. PTR Record (Pointer Record)**

- **What it does:** Maps an **IP address back to a domain name** (reverse DNS).
    
- **Example:**  
    `93.184.216.34 → example.com`
    

---

### 🔍 Summary Table:

|Record|Purpose|Example|
|---|---|---|
|A|Domain → IPv4|example.com → 93.184.216.34|
|AAAA|Domain → IPv6|example.com → 2606:...|
|NS|Points to name servers|ns1.exampledns.com|
|MX|Mail server|mail.example.com|
|CNAME|Domain alias|[www.example.com](http://www.example.com/) → example.com|
|TXT|Text info (SPF/DKIM)|"v=spf1 ..."|
|HINFO|Host info (CPU/OS)|"Intel", "Windows"|
|SOA|Domain authority info|admin email, serial, refresh, etc.|
|SRV|Service location info|SIP, XMPP servers, etc.|
|PTR|IP → Domain (reverse lookup)|93.184.216.34 → example.com|

## DNS Interrogation
### 🔍 **What is DNS Interrogation?**

**DNS Interrogation** is the process of **gathering information** from a domain's DNS records.

---

### 🎯 **Purpose of DNS Interrogation:**

- To collect details like:
    
    - **IP addresses**
        
    - **Subdomains**
        
    - **Mail servers**
        
    - **Name servers**
        
    - **Other DNS records**
        

This is often used in **reconnaissance** during **penetration testing** or **ethical hacking** to understand a target's network structure.

---

### 🧠 **What Can You Find with DNS Interrogation?**

|Info Type|Description|Example|
|---|---|---|
|A / AAAA records|Find the IP address of the domain|example.com → 93.184.216.34|
|MX records|Find the mail servers|mail.example.com|
|NS records|Find name servers handling DNS|ns1.exampledns.com|
|TXT records|Find SPF, DKIM, domain verification details|"v=spf1 include:..."|
|Subdomains|Discover services like `mail.example.com`|via tools like **dnsenum**|

---

### 🛠️ **Tools Used for DNS Interrogation:**

- `nslookup`
    
- `dig`
    
- `dnsenum`
    
- `dnsrecon`
    
- `theHarvester`
    
- `Fierce`
    
- Online tools like **SecurityTrails**, **DNSDumpster**, etc.
    

---

### 🧪 **Simple Example using `nslookup`:**

```bash
nslookup -type=mx example.com
```

🔸 This will show the **mail servers** for `example.com`.

```bash
nslookup -type=ns example.com
```

🔸 This will show the **name servers**.

---

### ⚠️ **Why is this useful in Cybersecurity?**

- Helps you **map the attack surface**
    
- Can expose **misconfigured DNS** entries
    
- Reveals potential **entry points** (like forgotten subdomains)

## DNS Zone Transfer
### 🌐 **What is a DNS Zone Transfer?**

A **DNS Zone Transfer** is a process where **DNS records (zone file)** are copied from one DNS server (usually a **primary/master**) to another (usually a **secondary/slave**).

---

### 🔁 **Why is it used?**

- For **redundancy**: So if one DNS server goes down, others still serve DNS queries.
    
- For **load balancing**: Distribute DNS traffic across multiple servers.
    

---

### 🚨 **Why is this important in cybersecurity?**

- If **zone transfers are not secured**, anyone can request a full list of DNS records for a domain.
    
- This means an attacker or pentester can **enumerate**:
    
    - All subdomains
        
    - Internal IPs or hostnames (if exposed)
        
    - Mail servers
        
    - Network structure


This gives a **complete view of the target network**, which is a goldmine during recon.

---

### 🧪 **Example: Zone Transfer with `dig` command**

```bash
dig @ns1.example.com example.com AXFR
```

- `@ns1.example.com`: The DNS server you're querying
    
- `example.com`: The target domain
    
- `AXFR`: Means "zone transfer request"
    

🔹 If the DNS server is **misconfigured**, it will reply with **all DNS records**.

---

### ✅ **Properly Configured DNS Server:**

- Only allows **trusted secondary servers** to request zone transfers.
    
- Uses **TSIG keys** (Transaction Signatures) for authentication.
    
- Blocks **AXFR** requests from the public.
    

---

### ⚠️ **Risks of Misconfigured Zone Transfers:**

|Risk|Description|
|---|---|
|Network exposure|Reveals all domain records (subdomains, IPs, etc.)|
|Internal data leak|Might include **internal-only addresses**|
|Attack surface expansion|Helps attackers plan phishing, subdomain takeover, etc.|

---

### 🕵️ **Why Pentesters Love It**

Zone transfer = **network treasure map**  
It's a passive method that can instantly reveal a lot without alerting defenses.

## DNS Zone Transfer Attack

`dnsenum` is a **Perl-based command-line tool** used for DNS enumeration. It helps penetration testers and ethical hackers gather DNS information about a target domain. This process is essential during the **information gathering/reconnaissance phase** of a penetration test.

---

### 🔍 What `dnsenum` Does:

It automates several tasks related to DNS reconnaissance, such as:

1. **Domain to IP resolution**
    
2. **Finding DNS records**: A, MX, NS, TXT, SOA, etc.
    
3. **Brute-forcing subdomains** (if a wordlist is supplied)
    
4. **Zone transfer testing** (`AXFR`)
    
5. **Identifying hostnames** through Google scraping (optional)
    
6. **Reverse lookups** on IP ranges
    
7. **WHOIS lookups**

---

### 🛠️ Basic Usage:

```bash
dnsenum example.com
```

---

### 🔧 Common Options:

|Option|Description|
|---|---|
|`--dnsserver <server>`|Specify a DNS server to use|
|`--enum`|Perform a full enumeration|
|`-f <file>`|Brute force using a list of subdomains|
|`--threads <num>`|Number of threads for speed|
|`--noreverse`|Disable reverse lookups|
|`--subfile <file>`|Save subdomains to a file|
|`--output <file>`|Save output to a file|

---

### 🧪 Example:

```bash
dnsenum --enum -f subdomains.txt example.com
```

This command performs full enumeration and uses a custom subdomain wordlist.

---

### 📌 Use Case in Pentesting:

- Reconnaissance before attacking web apps.
    
- Checking for misconfigured DNS servers (e.g., vulnerable to zone transfers).
    
- Gathering possible subdomains or internal IPs.
    

---

### 🔐 Pro Tip:

Zone transfers (`AXFR`) are often misconfigured in dev/test environments. If allowed, they can reveal all DNS zone data — a goldmine during pentests!

---

Performing a **zone transfer attack (AXFR)** is a classic DNS reconnaissance technique. It's used to check whether a DNS server is misconfigured and allows unauthorized zone transfers — which can leak a **full list of internal hostnames and IP addresses**.

This should **only be done in a legal, authorized environment** (e.g., in a lab, pentest, or CTF challenge) — because trying it on unauthorized networks is illegal.

---

## 🧠 What is Zone Transfer?
A **zone transfer (AXFR)** is a type of DNS transaction where a DNS server shares its zone file (which includes all records for a domain) with another DNS server. If it's not properly secured, anyone can request this information.

---

## ✅ Steps to Perform a Zone Transfer Attack

### **1. Find the Name Servers (NS Records)**

Use `dig` or `nslookup` to find the domain's name servers:

```bash
dig ns example.com
```
or
```bash
nslookup -type=ns example.com
```

You'll get a list like:
```
ns1.example.com
ns2.example.com
```

---

### **2. Attempt the Zone Transfer**

Now try AXFR on the name servers using:

#### 🛠️ Using `dig`
```bash
dig AXFR example.com @ns1.example.com
```

If it works, you’ll get a **full DNS zone dump** — including A, MX, TXT, and other records.

---

#### 🛠️ Using `dnsenum`
```bash
dnsenum --enum example.com
```
This will automatically try zone transfers as part of its enumeration.

---

#### 🛠️ Using `dnsrecon`
```bash
dnsrecon -d example.com -t axfr
```

---

### ❌ If Zone Transfer Fails:
You’ll see an error like:
```
Transfer failed.
```
or
```
; Transfer failed.
```
Which means the server is properly secured.

---

## 🔒 How to Prevent Zone Transfer Attacks

1. **Restrict AXFR to authorized IPs only** (typically secondary DNS servers).
2. **Use DNSSEC** for securing DNS integrity.
3. **Disable AXFR** entirely if not needed.
4. **Monitor DNS logs** for unauthorized AXFR attempts.

---

## 🧪 Example Lab Scenario

Let’s say you're testing `vulnweb.com`:

```bash
dig ns vulnweb.com
```
→ Shows: `ns1.vulnweb.com`, `ns2.vulnweb.com`

Then:

```bash
dig AXFR vulnweb.com @ns1.vulnweb.com
```

If successful, it may return:

```
www          3600 IN A 192.168.1.10
mail         3600 IN A 192.168.1.20
ftp          3600 IN A 192.168.1.30
```

This gives insight into internal infrastructure.
