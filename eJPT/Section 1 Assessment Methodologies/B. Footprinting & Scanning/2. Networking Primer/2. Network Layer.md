### Network Layer (Layer 3) – OSI Model

- The **Network Layer** is responsible for **logical addressing, routing, and packet forwarding** across different networks.
    
- It ensures that **data packets** can travel from the **source device** to the **destination device**, even when those devices are on **separate or distant networks**.
	
-  Its primary goal is to determine the **optimal path** for data to travel from the source to the destination
    
- This layer utilizes **IP addresses** (logical addresses) to uniquely identify devices and determine routing paths.
    
- Core functions include:
    
    - **Routing**: Selecting the most efficient path using routing protocols (e.g., OSPF, BGP, RIP).
        
    - **Logical addressing**: Assigning and recognizing IP addresses (IPv4/IPv6).
        
    - **Fragmentation and reassembly**: Breaking down large packets and reassembling them at the destination (especially with IPv4).
        
    - **Encapsulation**: Wrapping the Transport Layer data (e.g., TCP segments) in IP packets.
        
- Devices operating at this layer include **routers** and **Layer 3 switches**.
    
- Protocols at this layer: **IP (Internet Protocol), ICMP (used for diagnostics like ping/traceroute), IGMP**, etc.
    
- The Network Layer is crucial for enabling **internetwork communication**, abstracting the complexities of the underlying physical links.

### Network Layer Protocols (Layer 3 – OSI Model)

Several critical protocols function at the **Network Layer** to manage **logical addressing, routing, error handling**, and **diagnostics**. Below are the most prominent ones:

---

#### 🛰 **1. Internet Protocol (IP)**

The **core protocol** of the network layer that provides logical addressing and routing for data packets.

- **IPv4 (Internet Protocol version 4):**
    
    - Uses **32-bit addresses** (e.g., `192.168.1.1`)
        
    - Supp orts approximately **4.3 billion unique addresses**
        
    - Commonly used; includes features like **fragmentation**, **checksum**, and **header fields** for routing.
        
- **IPv6 (Internet Protocol version 6):**
    
    - Uses **128-bit addresses** (e.g., `2001:0db8:85a3::8a2e:0370:7334`)
        
    - Vastly larger address space (≈ 340 undecillion addresses)
        
    - Built-in **security (IPsec)** and improved **packet processing**
        
    - Eliminates the need for NAT in many scenarios
        

---

#### 🛠 **2. Internet Control Message Protocol (ICMP)**

- Primarily used for **error reporting**, **network diagnostics**, and **status queries**.
    
- Not used for data transmission, but crucial for **network troubleshooting**.
    
- Common ICMP message types:
    
    - **Echo Request / Echo Reply** – used by `ping` to test reachability.
        
    - **Destination Unreachable** – signals routing or delivery issues.
        
    - **Time Exceeded** – used by `traceroute` to track packet hops.
        
- Operates within IP but is **not a transport layer protocol** like TCP/UDP.

### Internet Protocol (IP) – Network Layer Protocol

- The **Internet Protocol (IP)** is a **core protocol** in the TCP/IP suite that serves as the **foundation of modern internetwork communication**, including the Internet.
    
- IP operates at **Layer 3 (Network Layer)** of the **OSI model**.


#### 🔧 **Key Responsibilities of IP:**

1. **Logical Addressing:**
    
    - Assigns **IP addresses** (IPv4/IPv6) to uniquely identify hosts on a network.
        
    - Ensures devices can be addressed independently of their physical location.
        
2. **Routing:**
    
    - Determines the **best path** for data packets to travel across interconnected networks.
        
    - Works in coordination with **routing protocols** (e.g., OSPF, BGP) and **routers** to move packets from source to destination.
        
3. **Packet Fragmentation & Reassembly:**
    
    - Breaks large packets into smaller fragments to fit within the **Maximum Transmission Unit (MTU)** limits of the underlying network.
        
    - Reassembles fragments at the destination to reconstruct the original data.
        
4. **Encapsulation:**
    
    - Encapsulates **Transport Layer segments** (e.g., TCP/UDP) into **IP packets (datagrams)** for delivery.
        

#### 🌐 **How IP Enables Communication:**

- IP provides a **standardized method** for addressing and locating devices.
    
- Ensures **interoperability** across diverse hardware and operating systems.
    
- Facilitates communication between devices on **different LANs, subnets, or global networks** like the Internet.
    

#### 📎 Versions of IP:

- **IPv4** – Uses 32-bit addresses; most widely deployed.
    
- **IPv6** – Uses 128-bit addresses; designed to overcome IPv4 limitations.

### Internet Protocol (IP) Versions

There are two major versions of IP in use today — **IPv4** and **IPv6**. Both serve the purpose of identifying devices across networks, but differ in format, address size, and capabilities.

---

#### 🌐 **IPv4 (Internet Protocol version 4)**

- **Most widely deployed IP version** in current networks.
    
- Uses **32-bit addressing**, allowing for approximately **4.3 billion unique addresses**.
    
- Represented in **dotted decimal format**:  
    Example → `192.168.0.1`
    
- Each IPv4 address is composed of **4 octets (8 bits each)**, separated by dots.
    
- IPv4 supports features like:
    
    - **Subnetting**
        
    - **Network Address Translation (NAT)**
        
    - **Broadcast communication**
        
- Due to address exhaustion, IPv4 is gradually being supplemented (not entirely replaced) by IPv6.
    

---

#### 🌍 **IPv6 (Internet Protocol version 6)**

- Developed to overcome the **limitations of IPv4**, especially address exhaustion.
    
- Uses **128-bit addressing**, allowing for ~**340 undecillion unique addresses**.
    
- Represented in **hexadecimal format**, separated by colons:  
    Example → `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
    
- Leading zeros can be **omitted**, and consecutive sections of zeros can be **compressed** using `::`:  
    Example → `2001:db8:85a3::8a2e:370:7334`
    
- Key enhancements over IPv4:
    
    - **No need for NAT** (public addresses for every device)
        
    - **Integrated IPsec** for security
        
    - **Simplified header** structure
        
    - **No broadcast**, uses multicast and anycast instead
        
    - **Auto-configuration** (SLAAC)

### 🛰️ **Internet Protocol (IP) – Core Functionalities**

The Internet Protocol (IP) enables **efficient, scalable, and structured communication** across interconnected networks. Below are the key functions and concepts associated with IP:

---

#### 🧭 **1. Logical Addressing**

- Each **network interface** is assigned a **unique IP address** that logically identifies a device on a network.
    
- IP addresses are:
    
    - **Hierarchical** in nature (network and host portions).
        
    - Defined using **subnetting**, **network classes**, and **CIDR (Classless Inter-Domain Routing)** notation.
        
    - Examples: `192.168.1.10/24` (CIDR) or Class A/B/C based structures.


---

#### 📦 **2. Packet Structure**

- IP breaks down data into **packets**, each containing:
    
    - **Header**: Contains control information like:
        
        - Source & Destination IP addresses
            
        - IP version (IPv4/IPv6)
            
        - Time-To-Live (TTL)
            
        - Protocol type (e.g., TCP, UDP)
            
        - Header checksum, Fragment offset, etc.
            
    - **Payload**: Carries the actual data passed from the Transport Layer.
        

---

#### ✂️ **3. Fragmentation and Reassembly**

- When a packet is **too large** for the MTU of a link:
    
    - IP **fragments** the packet into smaller pieces.
        
    - Each fragment carries identification and offset info.
        
- At the **destination**, the fragments are **reassembled** to reconstruct the original data packet.
    

---

#### 🧑‍🤝‍🧑 **4. IP Addressing Types**

- **Unicast**: One-to-one communication (e.g., sending a file to a specific host).
    
- **Broadcast**: One-to-all communication within a local subnet (`255.255.255.255` for IPv4).
    
- **Multicast**: One-to-many communication to a selected group of hosts (e.g., `224.0.0.1` for IPv4).
    

---

#### 🪢 **5. Subnetting**

- Divides a large IP network into **smaller, manageable sub-networks**.
    
- Benefits:
    
    - Improves **network performance** and **security**.
        
    - Reduces **broadcast traffic**.
        
    - Enables **efficient IP address allocation**.
        

---

#### ⚙️ **6. Internet Control Message Protocol (ICMP)**

- A supporting protocol for IP, used for:
    
    - **Diagnostics** and **error reporting**.
        
    - Examples: `ping` (Echo Request/Reply), `traceroute` (Time Exceeded).
        
- ICMP messages help detect unreachable hosts, route loops, and more.


---

#### 🔄 **7. Dynamic Host Configuration Protocol (DHCP)**

- **Not a part of IP**, but works closely with it to **dynamically assign IP addresses** to devices.
    
- Automates the network configuration process:
    
    - Assigns IP, Subnet Mask, Gateway, DNS info.
        
    - Prevents address conflicts and reduces manual work.

### 📦 **IPv4 Header Format**

The **IPv4 header** consists of multiple fields that provide **information for routing, delivery, fragmentation, and protocol handling**. Here's a breakdown of the key fields:

---

#### 🧠 **Basic Header Fields (20 bytes minimum)**

![[Pasted image 20250420215107.png]]

| **Field**                  | **Size** | **Purpose**                                                                                                           |
| -------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------- |
| **Version**                | 4 bits   | Indicates the IP version. For IPv4, this is always `4`.                                                               |
| **Header Length (IHL)**    | 4 bits   | Specifies the length of the IP header in 32-bit words. Minimum is 5 (i.e., 20 bytes), maximum is 15 (i.e., 60 bytes). |
| **Type of Service (ToS)**  | 8 bits   | Used to specify packet priority and quality of service (QoS). Includes **DSCP** and **ECN** fields.                   |
| **Total Length**           | 16 bits  | Total length of the entire packet (header + data). Max size: **65,535 bytes**.                                        |
| **Identification**         | 16 bits  | Used during packet fragmentation to uniquely identify a packet and reassemble its fragments.                          |
| **Flags**                  | 3 bits   | Controls fragmentation: • Bit 0: Reserved (always 0) • Bit 1: Don't Fragment (DF) • Bit 2: More Fragments (MF)        |
| **Fragment Offset**        | 13 bits  | Indicates the position of a fragment in the original packet.                                                          |
| **Time To Live (TTL)**     | 8 bits   | Limits the lifetime of the packet. Decrements by 1 at each hop; discarded when it reaches 0. Prevents routing loops.  |
| **Protocol**               | 8 bits   | Identifies the **upper-layer protocol**: • `1` for ICMP • `6` for TCP • `17` for UDP                                  |
| **Header Checksum**        | 16 bits  | Validates the integrity of the IP header. Routers recalculate this on each hop.                                       |
| **Source IP Address**      | 32 bits  | IP address of the sender.                                                                                             |
| **Destination IP Address** | 32 bits  | IP address of the intended recipient.                                                                                 |

---

#### 🧩 **Optional Fields (if header > 20 bytes)**

| **Field**   | **Purpose**                                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------------------------ |
| **Options** | Used for testing, debugging, or specialized routing (e.g., source routing, record route). Rarely used in practice. |
| **Padding** | Ensures the header is a multiple of 32 bits.                                                                       |

---

### 🧠 Memory Tip:

Think of the **IPv4 header** as a "passport" for a packet — it carries all the essential info needed for the journey across networks.

### 🌐 IPv4 Addresses

IPv4 is the **most commonly used version** of the Internet Protocol and is still widely in use despite the emergence of IPv6.

---

#### 🧮 **Structure**

- An **IPv4 address** is **32 bits** in length.
    
- It is divided into **4 octets** (8 bits each), separated by dots.
    
- Each octet can range from **0 to 255** (since 2⁸ = 256 values).
	
- You can find the details about the special use of IPv4 addresses in RFC5735. 
    
- Example:  
    `192.168.1.1` → Binary representation:  
    `11000000.10101000.00000001.00000001`
    

---

#### 📌 **Key Characteristics**

![[Pasted image 20250420215454.png]]

- Represented in **dotted decimal format**: `x.x.x.x` (e.g., `10.0.0.1`)
    
- Each IPv4 address consists of:
    
    - **Network portion** – Identifies the network.
        
    - **Host portion** – Identifies a specific device on the network.
        
- Subnet masks (e.g., `/24` or `255.255.255.0`) help determine how many bits belong to the network vs host portion.


---
