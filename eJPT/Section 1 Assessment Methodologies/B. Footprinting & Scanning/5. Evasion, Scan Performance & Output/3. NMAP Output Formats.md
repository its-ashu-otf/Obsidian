# NMAP Output Formats

```bash
OUTPUT:
             -oN/-oX/-oS/-oG <file>: Output scan in normal, XML, s|<rIpt kIddi3,
                and Grepable format, respectively, to the given filename.
             -oA <basename>: Output in the three major formats at once
             -v: Increase verbosity level (use -vv or more for greater effect)
             -d: Increase debugging level (use -dd or more for greater effect)
             --reason: Display the reason a port is in a particular state
             --open: Only show open (or possibly open) ports
             --packet-trace: Show all packets sent and received
             --iflist: Print host interfaces and routes (for debugging)
             --append-output: Append to rather than clobber specified output files
             --resume <filename>: Resume an aborted scan
             --noninteractive: Disable runtime interactions via keyboard
             --stylesheet <path/URL>: XSL stylesheet to transform XML output to HTML
             --webxml: Reference stylesheet from Nmap.Org for more portable XML
             --no-stylesheet: Prevent associating of XSL stylesheet w/XML output
```

## 📘 Nmap Output Formats: Complete Breakdown

When you run a scan with `nmap`, you often want to **save the results** for analysis, reporting, or parsing by other tools.

**Nmap supports multiple output formats**:

|Format|Option|File extension|Best for|
|:--|:--|:--|:--|
|Normal|`-oN`|`.nmap`|Human-readable reports|
|XML|`-oX`|`.xml`|Machine-readable; parsing with tools|
|Grepable|`-oG`|`.gnmap`|Simple parsing with grep/awk/sed|
|JSON|`-oJ`|`.json`|Structured data (available from Nmap 7.93)|
|Script Kiddie (interactive)|`-oS`|`.nmap`|Fun obfuscated output (rarely used)|
|All formats together|`-oA`|(3 files: `.nmap`, `.xml`, `.gnmap`)|Save everything in one command|

---

### 1. Normal Output (`-oN`)

- **Command:** `nmap -oN output.nmap <target>`
    
- **Purpose:** Human-friendly, easy to read and share.
    
- **Details:** Shows all scan information as if printed on the terminal (ports, states, services, etc.)


✅ Best when manually reviewing.

🛠 Example:

```bash
nmap -sV -oN scan_result.nmap 192.168.1.1
```

📄 Output example:

```
Starting Nmap 7.94 ( https://nmap.org ) at 2025-04-28
Nmap scan report for 192.168.1.1
Host is up (0.0010s latency).
PORT     STATE SERVICE VERSION
22/tcp   open  ssh     OpenSSH 7.6p1
80/tcp   open  http    Apache httpd 2.4.29
```

---

### 2. XML Output (`-oX`)

- **Command:** `nmap -oX output.xml <target>`
    
- **Purpose:** Machine-friendly; can be parsed easily.
    
- **Details:** Well-structured XML containing every scan detail.


✅ Perfect for feeding into analysis tools (e.g., `xsltproc`, `Nmap Parser` libraries, SIEM ingestion).

🛠 Example:

```bash
nmap -sV -oX scan_result.xml 192.168.1.1
```

📄 Output (partial example):

```xml
<nmaprun>
    <host>
        <status state="up" reason="syn-ack"/>
        <address addr="192.168.1.1" addrtype="ipv4"/>
        <ports>
            <port protocol="tcp" portid="22">
                <state state="open"/>
                <service name="ssh" version="OpenSSH 7.6p1"/>
            </port>
        </ports>
    </host>
</nmaprun>
```

---

### 3. Grepable Output (`-oG`)

- **Command:** `nmap -oG output.gnmap <target>`
    
- **Purpose:** Quick parsing with grep, sed, awk.
    
- **Details:** Each line has key information, structured to be easily processed.


✅ Great for custom scripting, quick analysis.

🛠 Example:

```bash
nmap -sV -oG scan_result.gnmap 192.168.1.1
```

📄 Output example:

```
Host: 192.168.1.1 ()   Status: Up
Host: 192.168.1.1 ()   Ports: 22/open/tcp//ssh///, 80/open/tcp//http///
```

**Example usage with grep:**

```bash
grep "/open/" scan_result.gnmap
```

→ Quickly extracts all open ports.

> ⚠️ _Note:_ Nmap has deprecated `-oG` for some detailed output (use with caution if depending on newer features).

---

### 4. JSON Output (`-oJ`) [NEW in Nmap 7.93+]

- **Command:** `nmap -oJ output.json <target>`
    
- **Purpose:** Structured JSON data output for modern apps and APIs.
    
- **Details:** Full scan results in JSON, great for web interfaces and automation.


✅ Useful in modern ecosystems where JSON is the standard.

🛠 Example:

```bash
nmap -sV -oJ scan_result.json 192.168.1.1
```

📄 Output (partial example):

```json
{
  "nmap": {
    "scanstats": {
      "timestr": "Mon Apr 28 12:00:00 2025",
      "elapsed": "5.32",
      "uphosts": "1",
      "downhosts": "0",
      "totalhosts": "1"
    },
    "scan": {
      "192.168.1.1": {
        "ports": [
          {
            "portid": "22",

            "state": "open",
            "service": {
              "name": "ssh",
              "version": "OpenSSH 7.6p1"
            }
          }
        ]
      }
    }
  }
}
```

---

### 5. Script Kiddie Mode (`-oS`)

- **Command:** `nmap -oS output.nmap <target>`
    
- **Purpose:** For fun; outputs in "leet" speak.
    
- **Details:** Obfuscates the output text into hacker-style formatting (e.g., `h4x0r t3xt`).
    

✅ Fun in CTFs and memes, but not practical.

🛠 Example:

```bash
nmap -oS scan_result_skr1pt_k1dd13.nmap 192.168.1.1
```

📄 Output:

```
Starting Nmap 7.94 at 2025-04-28
Nmap scan report for 192.168.1.1
Host is up (0.0010s latency).
PORT     STATE SERVICE
22/tcp   0p3n  ssh
80/tcp   0p3n  http
```

> ⚠️ _Just for fun. Never use this for real documentation._

---

### 6. Output All Formats (`-oA`)

- **Command:** `nmap -oA <basename> <target>`
    
- **Purpose:** Saves output as `.nmap`, `.xml`, and `.gnmap` **at once**.
    
- **Details:** Good for thoroughness — no need to re-run a scan just to get a different format.


✅ Best practice during professional engagements.

🛠 Example:

```bash
nmap -sV -oA scan_result 192.168.1.1
```

This creates:

- `scan_result.nmap`
    
- `scan_result.xml`
    
- `scan_result.gnmap`

# Import NMAP Scan Results into Metasploit Framework

You can **import Nmap scan results** into **Metasploit Framework** to make post-scan analysis, exploitation, and vulnerability assessment easier.

Metasploit has a built-in utility called **`db_import`** that allows you to import Nmap scan results directly into its database. After importing, you can use Metasploit's features to interact with the results, such as running further exploits, scanning for vulnerabilities, and managing targets.

Here's a step-by-step guide on how to import Nmap scan results into Metasploit.

### 1. **Perform a Nmap Scan and Save the Output**

First, run a Nmap scan and save the output in **XML** format (which is the preferred format for Metasploit).

```bash
nmap -sS -sV -oX scan_results.xml 192.168.1.0/24
```

Here, we are performing a **SYN Scan** (`-sS`) to detect open ports and services (`-sV`), and saving the output in **XML** format (`-oX`).

### 2. **Start Metasploit Framework**

Launch the **Metasploit Framework** by running the following command in your terminal:

```bash
msfconsole
```

### 3. **Set Up Metasploit Database (if not already configured)**

Metasploit uses a database (PostgreSQL) to store the information about hosts, services, and vulnerabilities. Before importing, ensure that the Metasploit database is configured and started:

```bash
msfdb init
```

This command initializes the database, creates necessary tables, and ensures that Metasploit can access it.

### 4. **Import the Nmap XML Results**

Once inside **msfconsole**, use the `db_import` command to import the Nmap XML scan results.

```bash
db_import /path/to/scan_results.xml
```

Replace `/path/to/scan_results.xml` with the actual path to the Nmap XML file you want to import.

Metasploit will now parse the XML file and import the data into the database, creating entries for hosts, ports, services, and other scan details.

### 5. **Verify the Import**

You can check the imported data using the `hosts` and `services` commands in Metasploit:

```bash
hosts
```

This will list all the hosts discovered in the scan.

```bash
services
```

This will display the services and ports discovered on each host.

### 6. **Use Metasploit's Capabilities with Imported Data**

Now that the Nmap scan results are in Metasploit, you can use the data in a variety of ways:

- **Vulnerability Scanning:** You can use Metasploit to search for specific vulnerabilities in the imported services.
    
    ```bash
    search type:exploit name:service_name
    ```
    
- **Running Exploits:** If you want to run an exploit against a specific service or host, use the `use` command and the `exploit` module.
    
    ```bash
    use exploit/windows/smb/ms17_010_eternalblue
    set RHOSTS 192.168.1.100
    run
    ```
    
- **Auxiliary Scanning:** You can use auxiliary modules to perform further scans or gather more information on the hosts and services you discovered.
    
    ```bash
    use auxiliary/scanner/http/dir_scanner
    set RHOSTS 192.168.1.100
    run
    ```
    

### 7. **Saving Data for Future Use**

You can also **export** data from Metasploit after interacting with it:

```bash
db_export -f xml /path/to/output.xml
```

This will export the database content to an XML file that can be used in future scans or analysis.

---

### Bonus: Automating the Process with a Script

You can automate the entire process by creating a script that runs the Nmap scan and imports the results directly into Metasploit. Here’s an example:

```bash
#!/bin/bash

# Perform Nmap scan
nmap -sS -sV -oX scan_results.xml 192.168.1.0/24

# Start msfconsole and import results
msfconsole -q -x "db_import scan_results.xml; exit"
```

This script runs the Nmap scan, saves the results, and then imports them directly into Metasploit.

---

### Troubleshooting:

- **Nmap Output Not Parsing Properly:** Ensure that the Nmap XML is well-formed and does not contain any errors.
    
- **Database Issues:** If you're facing database connection issues, try restarting the PostgreSQL service used by Metasploit (`sudo service postgresql restart`).
    
- **Missing Data After Import:** Double-check the Nmap scan to ensure you're capturing all relevant details (ports, services, versions).
    

---

### In Summary:

- **Run Nmap** with the `-oX` option to save results as XML.
    
- **Import XML** results into Metasploit with `db_import`.
    
- **Analyze** and **exploit** the data inside Metasploit using various commands and modules.
    


## Using **`db_nmap`** to Save Nmap Results Directly in Metasploit

The **`db_nmap`** command is a convenient way to run an Nmap scan and have the results automatically imported into the Metasploit database. This saves the effort of running Nmap separately and importing its results manually into the framework.

Here's the correct approach to do this:

### 1. **Start Metasploit Framework**

First, open **Metasploit** by typing:

```bash
msfconsole
```

### 2. **Run `db_nmap` Command**

Once inside **msfconsole**, use the `db_nmap` command to run your Nmap scan and automatically import the results into the Metasploit database.

**Syntax for `db_nmap`:**

```bash
db_nmap [options] <target>
```

You can use the same Nmap options as you would normally, such as `-Pn`, `-sS`, `-sV`, and `-O`.

**Example:**

```bash
db_nmap -Pn -sS -sV -O 192.168.1.100
```

**Explanation:**

- `-Pn` — Treat the target as alive, even if ICMP (ping) is blocked.
    
- `-sS` — Perform a SYN scan (stealth scan).
    
- `-sV` — Detect versions of services running on the open ports.
    
- `-O` — Enable OS detection.
    

This command will perform the Nmap scan and automatically save the results (hosts, services, OS, etc.) directly in the **Metasploit database**.

### 3. **Verify the Results in Metasploit**

Once the scan is complete, you can use the following commands to verify the results and interact with the data:

- **List the Hosts:**
    

```bash
hosts
```

This will list all the hosts discovered in the Nmap scan, including the target IP addresses.

- **List the Services:**
    

```bash
services
```

This will list all the services and ports discovered on the hosts.

### 4. **Interacting with the Imported Data**

Once the data is imported into Metasploit, you can proceed to:

- **Search for Exploits:**
    

You can search for known vulnerabilities based on the services discovered using:

```bash
search type:exploit name:<service_name>
```

- **Run Exploits:**
    

For example, to run an exploit against a service:

```bash
use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS 192.168.1.100
run
```

- **Auxiliary Scans:**
    

You can also run auxiliary modules against the discovered hosts and services:

```bash
use auxiliary/scanner/http/dir_scanner
set RHOSTS 192.168.1.100
run
```

### 5. **Exporting Results (Optional)**

If you want to save the data externally for future use, you can export it from Metasploit's database:

```bash
db_export -f xml /path/to/exported_results.xml
```

This will export the results into an XML file, which can be shared or used for further analysis.

---

### Summary

1. **Use `db_nmap`** inside Metasploit to run Nmap scans and save results directly into the Metasploit database.
    
2. **Check results** using `hosts` and `services` commands.
    
3. **Interact with the data** for further exploitation or analysis using Metasploit modules.
    

Using `db_nmap` is much more efficient when working within Metasploit because it integrates the scan results directly into the framework, making it easier to run subsequent exploits or auxiliary modules without needing to import external Nmap results.

# NMAP Grepable Output Format
The **Nmap Grepable Output Format** (`-oG`) is a useful way to generate scan results that are easy to parse using command-line tools like `grep` or `egrep` for further processing. Grepable output is less detailed than XML format but is much more compact and convenient for quick searches or automated parsing.

### Nmap Grepable Output (`-oG`)

The **`-oG`** option in Nmap allows you to save the scan results in a **grep-friendly format**, which consists of a series of lines that contain information about hosts, open ports, and services.

### Basic Syntax:

```bash
nmap [options] -oG <output_file> <target>
```

- `-oG` — Output the results in **grepable format**.
    
- `<output_file>` — The file where the results will be saved.
    
- `<target>` — The target(s) to scan (IP addresses, IP ranges, or subnets).
    

**Example:**

```bash
nmap -sS -p 1-1000 -oG nmap_results.txt 192.168.1.100
```

This will perform a **SYN scan** (`-sS`) on ports 1-1000 and save the output in **grepable format** to `nmap_results.txt` for the target IP `192.168.1.100`.

### Grepable Output Format

After running the above scan, the file (`nmap_results.txt`) will contain results in a format like this:

```bash
# Nmap 7.92 scan initiated Thu Apr 28 12:34:56 2025 as: nmap -sS -p 1-1000 -oG nmap_results.txt 192.168.1.100
Host: 192.168.1.100 (target_name)  Status: Up
Host: 192.168.1.100  Ports: 22/open/tcp//ssh///, 80/open/tcp//http///
# Nmap done at Thu Apr 28 12:35:02 2025 -- 1 IP address (1 host up) scanned in 5.4 seconds
```

### Key Components of Grepable Format:

- **Host Information:**
    
    - `Host: <IP> (<hostname>) Status: <status>` — Host information such as IP address and the associated hostname.
        
    - `Ports: <port>/<protocol>/<state>` — The list of open ports, their associated protocol (TCP/UDP), and the state (open, closed, filtered).
        

The output can contain a **`#`** symbol at the beginning of the line, marking comments, such as the Nmap version and scan details.

### Using `egrep` to Process Nmap Grepable Output

Now, you can use **`egrep`** (or `grep` with extended regex) to filter specific information from the **grepable output**. `egrep` is more powerful than regular `grep` because it allows you to use extended regular expressions (which include features like `+`, `?`, `|`, `()` for grouping, etc.).

#### Example: Grepping Open Ports

To search for **open TCP ports** in the grepable output:

```bash
egrep "Ports:.*open/tcp" nmap_results.txt
```

This will display all lines that have **open TCP ports**. The output might look like this:

```bash
Host: 192.168.1.100  Ports: 22/open/tcp//ssh///, 80/open/tcp//http///
```

#### Example: Searching for Specific Port

To search for a specific open port, such as **port 22 (SSH)**:

```bash
egrep "Ports:.*22/open/tcp" nmap_results.txt
```

This will show you all hosts with port 22 open:

```plaintext
Host: 192.168.1.100  Ports: 22/open/tcp//ssh///
```

#### Example: Extracting IPs with Open Ports

To extract only the **IP addresses** of hosts with open **SSH (port 22)**:

```bash
egrep -o "Host: [0-9]+\.[0-9]+\.[0-9]+\.[0-9]+" nmap_results.txt
```

This will output:

```plaintext
Host: 192.168.1.100
```

#### Example: Filtering Hosts Based on OS Information

To filter hosts with **OS information** (i.e., lines that contain `OS-fingerprint`):

```bash
egrep "OS-fingerprint" nmap_results.txt
```

This would return something like:

```plaintext
Host: 192.168.1.100  OS-fingerprint: Linux 4.15
```

#### Example: Count Open Ports

If you want to count how many open ports were detected across all hosts:

```bash
egrep -o "open/tcp" nmap_results.txt | wc -l
```

This command extracts all occurrences of "open/tcp" and counts how many times it appears, which will give you the number of open TCP ports.

---

### Combining `egrep` with Nmap for More Complex Filtering

You can combine `egrep` with **other Nmap options** for more complex and flexible filtering.

For example, you could:

- Run an Nmap scan with `-oG` to save results.
    
- Use `egrep` to quickly search for specific ports or services.
    
- Combine multiple `egrep` filters using piping (`|`).
    

#### Example: Searching for Multiple Services

Suppose you want to find hosts with **both port 22 (SSH) and port 80 (HTTP)** open, you can pipe `egrep` results:

```bash
egrep "Ports:.*22/open/tcp" nmap_results.txt | egrep "Ports:.*80/open/tcp"
```

This command will give you only the hosts that have **both port 22 and port 80 open**.

---

### Summary of Key `egrep` Examples for Nmap Grepable Output:

- **Find open TCP ports:**
    
    ```bash
    egrep "Ports:.*open/tcp" nmap_results.txt
    ```
    
- **Search for specific port (e.g., port 22 for SSH):**
    
    ```bash
    egrep "Ports:.*22/open/tcp" nmap_results.txt
    ```
    
- **Extract only IP addresses of hosts with open ports:**
    
    ```bash
    egrep -o "Host: [0-9]+\.[0-9]+\.[0-9]+\.[0-9]+" nmap_results.txt
    ```
    
- **Find hosts with OS information:**
    
    ```bash
    egrep "OS-fingerprint" nmap_results.txt
    ```
    
- **Count the number of open TCP ports:**
    
    ```bash
    egrep -o "open/tcp" nmap_results.txt | wc -l
    ```
    

Using `egrep` with **Nmap's grepable output** makes it easy to quickly parse and filter results, providing flexibility in your post-scan analysis. This approach is ideal for automation or when you're working with large scan results.

# 🔥 Pro Tips:

- Always **use `-oA`** during big engagements or CTFs — better safe than sorry!

# 🚀 Final Tip:

You can **redirect** (`>`) standard output manually too:

```bash
nmap -sV 192.168.1.1 > myoutput.txt
```

But using **`-oX`**, **`-oN`**, **`-oG`**, or **`-oJ`** is _better and cleaner_.
