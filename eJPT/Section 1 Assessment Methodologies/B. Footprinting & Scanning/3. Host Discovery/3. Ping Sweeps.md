## 🛠️ **Ping Sweeps** — Host Discovery via ICMP

A **ping sweep** is a **network scanning technique** used to identify **live hosts** (computers, servers, IoT devices, etc.) within a given **IP range**.

---

### 🧪 **How It Works**

- **Ping (ICMP Echo Request)** packets are sent to multiple IP addresses.
    
- Hosts that are **alive** respond with **ICMP Echo Reply** packets.
    
- The utility most commonly used: `ping` (available on Windows, Linux, macOS, etc.)

### 🔄 **ICMP Packet Details**

ICMP (Internet Control Message Protocol) uses specific message types and codes for communication.

|  Message Type | ICMP Type | Code | Description             |
| ------------- | --------- | ---- | ----------------------- |
| Echo Request  | 8         | 0    | Sent by source host     |
| Echo Reply    | 0         | 0    | Sent by target if alive |

#### 🧠 Quick Tip:

- `Type` defines the **function** of the ICMP message.
    
- `Code` provides **context** or **further meaning** for the Type.
    

---

### 💡 **Command-Line Usage Example**

#### Windows / Linux / macOS:

```bash
ping 192.168.1.1
```

For a range (using tools like Nmap or fping):

```bash
fping -a -g 192.168.1.0/24
```

Or using Nmap for ICMP sweep:

```bash
nmap -sn 192.168.1.0/24
```

---

### ❌ **No Reply ≠ Host Down**

If no ICMP Echo Reply is received, it **does not guarantee** the host is down. Possible reasons:

- 🔒 **Firewall** or IDS/IPS is blocking ICMP.
    
- 📶 **Network congestion** or latency.
    
- 💻 Host is temporarily unavailable or configured not to respond.
    

---

### ✅ **Pros & Cons of Ping Sweeps**

|Pros|Cons|
|---|---|
|Fast & simple|Easily blocked or filtered|
|Works across OSes|Generates noise (easily detectable)|
|Useful for small networks|Less effective on large/secured networks|

---

### 🛡️ **Defensive Measures**

To prevent ping-based host discovery:

- Block **ICMP Echo Requests** at the firewall.
    
- Rate-limit ICMP traffic.
    
- Use **host-based firewalls** to filter ping responses.

### 📄 **ICMP Header Breakdown**

- **Type**: Indicates the purpose or function of the ICMP message.
    
- **Code**: Provides additional information specific to the message Type.
    

---

### 🔁 **Ping Mechanism Using ICMP**

|ICMP Message|Type|Code|Description|
|---|---|---|---|
|Echo Request|8|0|Sent by source to test reachability|
|Echo Reply|0|0|Sent by destination to confirm it is alive|

---

### 🛠️ **What Happens During a Ping**

1. **Sender (Client)**:
    
    - Sends an **ICMP Echo Request** with `Type: 8`, `Code: 0`.
        
2. **Receiver (Target Host)**:
    
    - If alive and not blocking ICMP, responds with an **ICMP Echo Reply** with `Type: 0`, `Code: 0`.
        

---

### ❗ **No Response? Possible Reasons**

If **no ICMP Echo Reply** is received:

- 🔒 **Firewall** is blocking ICMP traffic.
    
- 📉 **Network congestion** or packet loss.
    
- 💤 **Target host** is down or temporarily unavailable.
    
- 🛡️ **Security settings** (e.g., ICMP disabled by sysadmin).
    

---

### ⚠️ **Important Note**

> Absence of a reply does **not always** mean the host is offline.

Interpreting ping results must consider:

- The **security posture** of the network.
    
- Whether **ICMP traffic is allowed** through firewalls or routers.
    
- **Host configuration** (some systems are set not to respond to ping).

# DEMO


Step 1: Open the lab link to access the Kali machine.

![[Pasted image 20250422000227.png]]

Step 2: Ping the target machine to see if it’s alive or not.

```bash
ping -c 5 demo.ine.local
```

![[Pasted image 20250422000239.png]]

We can observe that the target is not responding to the ping requests, so this does not confirm if it’s alive or down.

Step 3: Run a Nmap scan against the target.

```bash
nmap demo.ine.local
```


![[Pasted image 20250422000324.png]]

Nmap also could not detect whether the host was up or not. Many security tools first ping the host before they start scanning or exploiting the target. In that case, one has to use advanced Nmap options, i.e., `-A` or `-T5`, etc., in order to get the correct output.

In the nmap, there is one option, i.e., -Pn (Treat all hosts as online; skip host discovery). This option will force the scanning even if it has detected the target as down in host discovery.

Step 4: Running Nmap using the -Pn option to discover all alive ports.

```bash
nmap -Pn demo.ine.local
```


![[Pasted image 20250422000646.png]]

We can see multiple ports are open on the target machine.

Now, we will scan any random port that isn’t open. In this case, scan port 443. If the port is not open, we would receive “filtered” output from that port.

```bash
nmap -Pn -p 443 demo.ine.local
```

![[Pasted image 20250422000707.png]]

We can observe in the Nmap output that the host is up, but port 443 is filtered.

### About Filtered port:

Nmap cannot determine whether the port is open because packet filtering prevents its probes from reaching the port. The filtering could be from a dedicated firewall device, router rules, or host-based firewall software. These ports frustrate attackers because they provide so little information. Sometimes they respond with ICMP error messages such as type 3 code 13 (destination unreachable: communication administratively prohibited), but filters that simply drop probes without responding are far more common. This forces Nmap to retry several times just in case the probe was dropped due to network congestion rather than filtering. This slows down the scan dramatically.

Source: https://nmap.org/book/man-port-scanning-basics.html

Step 5: Similarly, if we want to discover the running application on port 80, we could use option -sV, and this option is used to determine the application version information.

```bash
nmap -Pn -sV -p 80 demo.ine.local
```

![[Pasted image 20250422000734.png]]

This is one of the ways we can discover a machine that is behind a firewall, forcing tools for scanning.
