Importing Nmap scan results into **Metasploit Framework (MSF)** is a common and powerful step in penetration testing. Here’s how to do it effectively:

---

# Import Nmap Results into MSF

#### **1. Perform an Nmap Scan and Save Output**

Use Nmap with the **XML output** format (`-oX`) which Metasploit can parse.

```bash
nmap -sS -sV -T4 -O -oX scan_results.xml <target-ip>
```

Example:

```bash
nmap -sS -sV -T4 -O -oX scan_results.xml 192.168.1.0/24
```

---

#### **2. Start Metasploit Console**

```bash
msfconsole
```

---

#### **3. Import the Nmap XML File**

Once inside Metasploit:

```bash
db_import /path/to/scan_results.xml
```

Example:

```bash
db_import /home/user/scan_results.xml
```

Metasploit will parse the XML and populate its database with discovered hosts, services, OS info, etc.

---

#### **4. Verify the Import**

Use these commands:

- Show all hosts:
    
    ```bash
    hosts
    ```
    
- Show all services:
    
    ```bash
    services
    ```
    
- Search for vulnerabilities (if applicable):
    
    ```bash
    vulns
    ```
    

---

### 🔍 Notes:

- Metasploit must be **connected to a database**. If not, use:
    
    ```bash
    db_status
    db_connect
    ```
    
- If you're using **MSF in Kali Linux**, the database usually auto-starts.
    

---

### 🎯 Bonus: Automate with Workspace

You can use workspaces to organize multiple scans:

```bash
workspace -a test_env
workspace test_env
db_import scan_results.xml
```

---

# How to perform nmap scan within metasploit framework

To perform an **Nmap scan within Metasploit Framework (MSF)** and have the results automatically imported into the database, you can use the built-in `db_nmap` command. This is essentially just running Nmap **from within** `msfconsole`.

---

### ✅ **Steps to Run Nmap Scan Inside MSF**

#### 1. **Start Metasploit Console**

```bash
msfconsole
```

#### 2. **Check Database Connection**

```bash
db_status
```

- If it's not connected, run:
    
    ```bash
    db_connect
    ```
    

#### 3. **Run Nmap Scan with `db_nmap`**

The syntax is the same as regular Nmap, just prefixed with `db_nmap`.

```bash
db_nmap -sS -sV -O -T4 <target-ip>
```

Example:

```bash
db_nmap -sS -sV -O -T4 192.168.1.105
```

This performs:

- `-sS`: SYN scan
    
- `-sV`: Service version detection
    
- `-O`: OS detection
    
- `-T4`: Aggressive timing
    

> All results are saved directly to MSF’s database.

#### 4. **View Results**

- Show hosts:
    
    ```bash
    hosts
    ```
    
- Show services:
    
    ```bash
    services
    ```
    
- Show discovered ports:
    
    ```bash
    vulns
    ```
    

---

### 🔄 Tips

- You can run `workspace -a <name>` to organize scans per environment.
    
- `db_nmap` doesn't support **all** Nmap options but works well for most recon needs.
