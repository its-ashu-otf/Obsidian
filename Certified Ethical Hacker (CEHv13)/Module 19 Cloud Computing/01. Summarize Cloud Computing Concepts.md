# Introduction to Cloud Computing
---

![[Pasted image 20250426212107.png]]

### **Cloud Computing Overview**

> Cloud computing is the **on-demand delivery** of IT services (like servers, storage, databases, networking, software) over the internet ("the cloud") on a **pay-as-you-go** basis.

**Examples:** Gmail, Facebook, Dropbox, Salesforce.com

---

### **Key Characteristics of Cloud Computing**

| Characteristic                | Description                                                                                                                        |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **On-Demand Self-Service**    | Users can provision resources automatically without human interaction with the provider.                                           |
| **Distributed Storage**       | Data is spread across multiple servers for better scalability and reliability. Security compliance can be a concern.               |
| **Rapid Elasticity**          | Resources can be quickly scaled **up or down** according to demand; appears almost unlimited to users.                             |
| **Automated Management**      | Cloud systems automate tasks to minimize user involvement, speed up processes, and reduce human error.                             |
| **Broad Network Access**      | Services are accessible over the network via standard protocols on various devices (laptops, mobiles, PDAs).                       |
| **Resource Pooling**          | Provider pools resources to serve multiple consumers dynamically in a multi-tenant model.                                          |
| **Measured Service**          | Resources are **metered** (pay-per-use model) — customers are charged based on consumption (e.g., storage, processing, bandwidth). |
| **Virtualization Technology** | Virtualization enables efficient and rapid scaling of resources — something physical environments can't easily do.                 |

---

### **Limitations of Cloud Computing**

|Limitation|Description|
|:--|:--|
|**Limited Control and Flexibility**|Organizations often have less control over the infrastructure, updates, and policies managed by the cloud provider.|
|**Proneness to Outages and Technical Issues**|Despite high reliability, cloud services can experience downtime, impacting business operations.|
|**Security, Privacy, and Compliance Issues**|Storing sensitive data in the cloud raises concerns about unauthorized access, data breaches, and compliance with regulations (like GDPR, HIPAA).|
|**Contracts and Lock-Ins**|Long-term contracts or proprietary technologies can make it difficult to switch providers without high costs or technical challenges.|
|**Dependence on Network Connections**|Cloud services require a stable internet connection; any disruption can affect access to critical resources.|
|**Potential Vulnerability to Attacks**|Since services are internet-accessible, they are more exposed to threats like DDoS attacks, data breaches, and exploitation of vulnerabilities.|
|**Difficulty in Migration**|Moving applications and data between different cloud providers can be complex, costly, and risky due to compatibility or format differences.|

# Types of Cloud Computing Services

---

### 1. **Infrastructure-as-a-Service (IaaS)**

![[Pasted image 20250426212510.png]]

- **Definition**: Provides basic IT resources like servers, storage, and networking over the cloud.
    
- **Examples**: Amazon EC2, Rackspace, Microsoft OneDrive.
    
- **Advantages**:
    
    - Dynamic infrastructure scaling.
        
    - Guaranteed uptime.
        
    - Automated administrative tasks.
        
    - Elastic Load Balancing (ELB).
        
    - Global accessibility.
        
- **Disadvantages**:
    
    - Higher risk of software security breaches.
        
    - Possible performance and connection speed issues.
        

---

### 2. **Platform-as-a-Service (PaaS)**

![[Pasted image 20250426212808.png]]

- **Definition**: Provides platforms to develop, test, and deploy applications without managing the infrastructure.
    
- **Examples**: Google App Engine, Salesforce, Microsoft Azure.
    
- **Advantages**:
    
    - Simplified app deployment.
        
    - Prebuilt business functionalities.
        
    - Lower security risks than IaaS.
        
    - Pay-per-use model.
        
    - Easy scalability.
        
- **Disadvantages**:
    
    - Vendor lock-in (hard to switch providers).
        
    - Data privacy concerns.
        
    - Integration issues with existing systems.
        

---

### 3. **Software-as-a-Service (SaaS)**

![[Pasted image 20250426212842.png]]

- **Definition**: Delivers software applications over the internet on-demand.
    
- **Examples**: Google Docs, Salesforce CRM, Freshbooks.
    
- **Advantages**:
    
    - Low cost.
        
    - Easy administration.
        
    - Accessible globally.
        
    - Highly compatible (no special hardware/software needed).
        
- **Disadvantages**:
    
    - Security and latency issues.
        
    - Fully dependent on internet connection.
        
    - Hard to switch between SaaS vendors.
        

---

### 4. **Identity-as-a-Service (IDaaS)**

![[Pasted image 20250426213431.png]]

- **Definition**: Cloud-based identity and access management services (IAM).
    
- **Examples**: Okta, OneLogin, Azure Active Directory.
    
- **Advantages**:
    
    - Centralized user management.
        
    - Improved security.
        
    - Simplified regulatory compliance.
        
    - Time-saving on user access management.
        
- **Disadvantages**:
    
    - Single server failures can disrupt service.
        
    - Vulnerable to account hijacking attacks.
        

---

### 5. **Security-as-a-Service (SECaaS)**

- **Definition**: Delivers security services like intrusion detection, SIEM, and anti-malware from the cloud.
    
- **Examples**: eSentire MDR, Switchfast, Foundstone Managed Security.
    
- **Advantages**:
    
    - Reduced cost.
        
    - Access to latest security tools.
        
    - Continuous protection.
        
    - Rapid provisioning.
        
- **Disadvantages**:
    
    - Increased attack surface.
        
    - Insecure APIs can be a risk.
        
    - Limited customization for business needs.
        
    - Account hijacking vulnerability.
        

---

### 6. **Container-as-a-Service (CaaS)**

- **Definition**: Provides container management and orchestration services through the cloud.
    
- **Examples**: Amazon EC2, Google Kubernetes Engine (GKE).
    
- **Advantages**:
    
    - Streamlined development of containerized apps.
        
    - High scalability.
        
    - Crash of one container doesn't affect others.
        
    - Improved patching and security.
        
- **Disadvantages**:
    
    - High operational overhead for developers.
        
    - Developers responsible for platform deployment.
        

---

### 7. **Function-as-a-Service (FaaS)**

- **Definition**: Serverless platform that lets you run functions/code without managing servers.
    
- **Examples**: AWS Lambda, Google Cloud Functions, Azure Functions.
    
- **Advantages**:
    
    - Pay only for use.
        
    - Easy deployment.
        
    - Highly scalable.
        
    - Quick security updates.
        
- **Disadvantages**:
    
    - High latency sometimes.
        
    - Memory limitations.
        
    - Debugging and monitoring are difficult.
        
    - Vendor lock-in risks.
        

---

### 8. **Anything-as-a-Service (XaaS)**

- **Definition**: Offers a wide range of services (not limited to IT) over the internet.
    
- **Examples**: AWS Elastic Beanstalk, Heroku, Apache Stratos.
    
- **Advantages**:
    
    - Highly scalable.
        
    - Location-independent.
        
    - Fault tolerance and reduced redundancy.
        
    - Reduces capital expenditure.
        
- **Disadvantages**:
    
    - Service outages possible due to internet dependency.
        
    - Performance issues during high usage.
        
    - Complex to troubleshoot.
        

---

### 9. **Firewall-as-a-Service (FWaaS)**

- **Definition**: Cloud-delivered firewall services that secure network traffic.
    
- **Examples**: Zscaler, Fortinet, Sophos.
    
- **Advantages**:
    
    - Protects multiple cloud deployments.
        
    - Improved network visibility.
        
    - Easier maintenance and standardized policies.
        
- **Disadvantages**:
    
    - Initial resistance to adoption.
        
    - Possible network latency.
        

---

### 10. **Desktop-as-a-Service (DaaS)**

- **Definition**: Virtual desktops delivered from the cloud.
    
- **Examples**: Amazon Workspaces, Citrix Managed Desktops, Azure Windows Virtual Desktop.
    
- **Advantages**:
    
    - Accessible globally.
        
    - Reduced downtime.
        
    - Low operational costs.
        
    - High flexibility and scalability.
        
- **Disadvantages**:
    
    - Security concerns.
        
    - Dependence on stable network connection.
        
    - High licensing costs.
        

---

### 11. **Mobile Backend-as-a-Service (MBaaS)**

- **Definition**: Provides backend services (e.g., databases, authentication) for mobile apps via API/SKDs.
    
- **Examples**: Firebase, AWS Amplify, Backendless.
    
- **Advantages**:
    
    - Faster app development.
        
    - Highly flexible and scalable.
        
    - Pay-as-you-go pricing.
        
- **Disadvantages**:
    
    - Security risks.
        
    - High initial setup costs.
        

---

### 12. **Machines-as-a-Service (MaaS)**

- **Definition**: Leasing machines and tracking their real-time usage and profits through the cloud.
    
- **Examples**: Industrial and IoT environments.
    
- **Advantages**:
    
    - Low upfront investment for clients.
        
    - Reliable income source for manufacturers.
        
    - Improved product tracking and quality.
        
- **Disadvantages**:
    
    - Expensive maintenance and repairs.
        
    - Replacing humans with machines leads to unemployment issues.

# Shared Responsibilities in Cloud

![[Pasted image 20250426214731.png]]

In cloud environments, it's very important to clearly separate what the _subscriber_ (the user or organization using the service) is responsible for, and what the _service provider_ (like AWS, Azure, or Google Cloud) is responsible for.  
This separation ensures:

- Prevention of conflict of interest, fraud, abuse, and errors.
    
- Detection of security control failures (such as information theft, security breaches, or evasion of controls).
    
- Limitation of any individual's or organization's control and influence.
    
- Assurance that tasks and responsibilities do not conflict with one another.

## Cloud Deployment Models

Cloud deployment selection depends on:

- Host location
    
- Security requirements
    
- Cloud service sharing
    
- Management capabilities
    
- Customization needs
    

---

### **1. Public Cloud**

![[Pasted image 20250426215700.png]]

- **What it is:** Services (apps, storage, servers) made available to the public over the Internet by a provider.
    
- **Examples:** AWS EC2, Google App Engine, Azure Services.
    
- **Advantages:**
    
    - Easy to use and cost-effective.
        
    - No maintenance needed.
        
    - Flexible with no long-term contracts.
        
- **Disadvantages:**
    
    - Lower security.
        
    - Less control.
        
    - Internet speed-dependent (can be slow).
        

---

### **2. Private Cloud**

![[Pasted image 20250426220217.png]]

- **What it is:** Cloud environment operated by a **single organization**, often behind a firewall.
    
- **Examples:** VMware vRealize Suite, SAP Cloud Platform.
    
- **Advantages:**
    
    - High security and compliance (HIPAA, PCI DSS, etc.).
        
    - Full control over data and hardware.
        
    - High performance (faster internal network).
        
- **Disadvantages:**
    
    - Expensive.
        
    - Requires on-site maintenance.
        

---

### **3. Community Cloud**

![[Pasted image 20250426220234.png]]

- **What it is:** Shared by several organizations with similar interests (e.g., healthcare, government agencies).
    
- **Examples:** Salesforce Health Cloud, Cisco Cloud Solutions.
    
- **Advantages:**
    
    - More affordable than private cloud.
        
    - Tailored for community needs.
        
    - Easier legal compliance.
        
- **Disadvantages:**
    
    - Resource competition among members.
        
    - Moderate security risks.
        
    - No clear liability if problems arise.
        

---

### **4. Hybrid Cloud**

![[Pasted image 20250426220248.png]]

- **What it is:** A mix of two or more clouds (private, public, community) working together.
    
- **Examples:** Microsoft Azure Hybrid Cloud.
    
- **Advantages:**
    
    - Flexibility and scalability.
        
    - Secure critical data privately, public for less critical.
        
    - Cost-effective if managed properly.
        
- **Disadvantages:**
    
    - Complex communication and integration.
        
    - Harder to achieve compliance.
        
    - Complex SLAs.
        

---

### **5. Multi-Cloud**

![[Pasted image 20250426220524.png]]

- **What it is:** Using services from **multiple cloud providers** (e.g., AWS + Azure + GCP).
    
- **Examples:** Azure Arc, Google Anthos.
    
- **Advantages:**
    
    - High reliability.
        
    - Avoid vendor lock-in.
        
    - Better performance and flexibility.
        
- **Disadvantages:**
    
    - Complex management.
        
    - Security risks (large attack surface).
        
    - Redundancy and overhead.
        

---

### **6. Distributed Cloud**

![[Pasted image 20250426220539.png]]

- **What it is:** Centralized cloud services that are distributed to different locations but controlled through a single interface.
    
- **Examples:** Google Distributed Cloud, Cloudflare CDN.
    
- **Advantages:**
    
    - High performance and reduced latency.
        
    - Edge computing capabilities.
        
    - Good for AI, ML, IoT applications.
        
- **Disadvantages:**
    
    - High setup costs.
        
    - Potential security vulnerabilities.
        
    - Complex troubleshooting.
        

---

### **7. Poly Cloud**

![[Pasted image 20250426220551.png]]

- **What it is:** Combines features/services from **different cloud providers into one unified platform**.
    
- **Examples:** AWS + GCP poly cloud setups.
    
- **Advantages:**
    
    - Extreme flexibility.
        
    - Optimized infrastructure and ROI.
        
    - Specialized services (e.g., AI/ML).
        
- **Disadvantages:**
    
    - Time-consuming and expensive setup.
        
    - High R&D costs.
        
    - Not ideal for small businesses.
